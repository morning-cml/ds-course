6.1 数组：线性表的推广

6.1.1 一维数组：它本来就是线性表

数组（array）是由类型相同的数据元素构成的有限序列。请注意这个定义里的两个关键词： 「类型相同」意味着每个元素占用的字节数一样，这是后面一切地址公式的前提； 「有限序列」意味着元素个数是固定的，一旦建立就不能随意增减。

一维数组 a[0..n-1] 的逻辑结构和线性表完全一致：有唯一的第一个元素、唯一的最后一个元素， 除首尾之外每个元素都有且仅有一个直接前驱和一个直接后继。所以我们可以直接说： 一维数组就是一种线性表，只是它额外约束了「元素等长」并且通常不允许插入删除。

那二维数组呢？A[m][n] 看上去是一张表格，有行有列，似乎比线性表复杂。但换个角度看： 如果我们把第 i 行的 n 个元素 a[i][0..n-1] 打包看成「一个元素」， 那么整个二维数组就退化成了一个长度为 m 的一维数组，只不过它的每个元素本身又是一个长度为 n 的线性表。换句话说：

二维数组 = 每个数据元素都是线性表的线性表

这句话可以一直套下去：三维数组的每个元素是二维数组，二维数组的每个元素是一维数组…… 所以教材里那句「数组是线性表的推广」，说的正是这种「元素本身又是线性表」的递归结构。 理解了这一层，后面「行优先 / 列优先」不过是选择了先走哪一层而已。

i 是一个长度为 4 的线性表 A = (R0, R1, R2) 又是一个长度为 3 的线性表 同理也可以把「每一列」当成元素，得到列向量视角 行视角 → 行优先存储；列视角 → 列优先存储

6.1.2 二维数组的两种视角

图 6-1 给了我们两种看待 A[m][n] 的方式，它们直接对应两种存储方案：

行向量视角（把行当元素）
A = (R0, R1, …, Rm−1)，其中每个 Ri = (a[i][0], a[i][1], …, a[i][n−1])。 按这个顺序把元素一个个排进内存，就是行优先存储。
列向量视角（把列当元素）
A = (C0, C1, …, Cn−1)，其中每个 Cj = (a[0][j], a[1][j], …, a[m−1][j])。 按这个顺序排进内存，就是列优先存储。

两种视角在数学上是完全对称的，没有谁更「正确」。但现实中的编程语言必须选一个作为默认约定， 这就造成了 C/C++/Java/Python 与 Fortran/MATLAB 之间的差异，也造成了考试里最爱考的那一类题： 「已知某元素地址，求另一元素地址」。做题前第一件事永远是看清楚题目说的是行优先还是列优先。

6.1.3 随机存取从哪来：等长元素 + 连续存放

线性表那一章我们讲过：顺序表可以 O(1) 按下标取值，链表不行。 数组是纯粹的「顺序存储」，它的随机存取能力来自两个条件同时成立：

  1. 所有元素等长：每个元素占 L 个字节，谁也不多谁也不少；
  2. 所有元素连续存放：第 k 个元素紧跟在第 k−1 个元素后面，中间没有空隙。

只要这两条成立，「第 k 个元素在哪里」就不再需要「从头一个个数过去」，而可以直接乘出来：

LOC(a[k]) = LOC(a[0]) + k × L

这就是随机存取（random access）：访问任意一个元素所需的计算量完全相同， 与 k 的大小无关，所以是 O(1)（见图 6-2）。 反过来说，只要破坏其中任何一条，随机存取立刻失效： 链表的结点是 new 出来的，地址不连续，只能顺藤摸瓜， 于是按下标访问退化成 O(n)；变长字符串数组因为元素不等长，也没法用一次乘法定位。

6.1.4 数组的 ADT：为什么通常只做「取值」和「赋值」

翻开任何一本教材，数组的抽象数据类型都短得可怜，基本只有两个操作： Value(A, index) 取值、Assign(A, index, e) 赋值。 （有的书写成 GetValue / SetValue，或者干脆用 A[i] 表示。） 与之配套的还有 InitArray（初始化）、DestroyArray（销毁）， 但它们属于「生老病死」，不算常规操作。

为什么数组不像线性表那样提供 Insert / Delete？原因有三条，一条比一条本质：

  • 结构一旦建立就固定不变。数组的维数和各维长度在初始化时就确定了， A[m][n] 的含义是「恰好 m×n 个元素」。插入一个元素会让它变成 m×n+1 个，这个形状根本不是一个合法的二维数组。
  • 插入会摧毁随机存取。如果允许在中间插一个元素、后面的元素整体后移， 那么每次插入都是 O(n)；更糟的是，一旦允许元素个数变化， 「连续 + 等长」的假设就要靠不断搬迁来维持，数组最大的优势就没了。
  • 数组的定位是「底层存储结构」。数组不是给人直接用的高层容器， 而是实现别的结构的砖头。顺序表要在中间插入时，会用数组 + 元素个数计数 + 容量 自己管理：把「有多少个有效元素」这件事交给一个额外的 length 变量， 而不是交给数组。这样数组本身保持纯粹，随机存取能力得以保留。
一句话串起来 数组 = 定长 + 等长 + 连续。定长让它没有插入删除，等长 + 连续让它有 O(1) 随机存取。 本章后面所有的压缩存储方案，本质上都是在「元素不再等长 / 不再连续」的情况下， 人为地重新造出一个下标映射函数，把随机存取能力抢回来。

6.2 多维数组的存储：行优先与列优先

6.2.1 行优先（Row-Major）：C/C++ 的选择

二维数组在逻辑上是二维的，但计算机内存是一维的，一根长长的地址轴。 所谓「存储」，就是把这 m×n 个元素排成一个队列塞进这根地址轴里。 排列方式不止一种，最常见的就是行优先（row-major order）： 先存第 0 行，再存第 1 行……同一行里从左到右依次存。

现在推导地址公式。设 A[m][n]，首元素 a[0][0] 的地址是 LOC(a[0][0])，每个元素占 L 个字节。要求 a[i][j] 的地址， 只需要回答一个问题：排在 a[i][j] 前面的元素一共有多少个？

  1. 第 0 行到第 i−1 行都是完整地排在它前面的，一共 i 行， 每行 n 个元素，所以有 i × n 个；
  2. 在它自己所在的第 i 行里，列号比 j 小的还有 j 个元素 （列号从 0 到 j−1）；
  3. 合计前面有 i × n + j 个元素，每个占 L 字节， 所以地址要在首地址上加上 (i × n + j) × L。
LOC(a[i][j]) = LOC(a[0][0]) + (i × n + j) × L

公式里的 i × n + j 其实就是元素 a[i][j] 在「拉直成一行」之后的下标， 我们把它叫做线性下标或一维序号，记作 k = i × n + j。 考试时如果你一时想不起公式，最快的办法就是举个小例子现场数： 比如 A[3][4] 里的 a[1][2]，前面有 1 整行（4 个）+ 本行 2 个 = 6 个， 于是 k = 6，与 1×4+2 = 6 完全一致。

为什么 C 语言「按行遍历」更快 行优先意味着 a[i][0..n−1] 在内存里是连续的一整段。 按行遍历时 CPU 缓存一次读入一整条 cache line（通常 64 字节，能装 16 个 int）， 后面十几个元素都是白送的；而按列遍历时，每次访问都要跳到 n × L 字节之外， 缓存几乎次次不命中。所以在 C/C++ 里写双重循环时，内层循环一定要遍历最后一个下标。

6.2.2 列优先（Column-Major）：Fortran / MATLAB 的选择

列优先的排法刚好反过来：先存第 0 列，再存第 1 列，同一列里从上到下依次存。 推导完全对称，只是「整块」的单位从「行」变成了「列」：

  1. 第 0 列到第 j−1 列都是完整的 j 列，每列 m 个元素，共 j × m 个；
  2. 本列中行号比 i 小的还有 i 个；
  3. 合计 j × m + i 个元素排在前头。
LOC(a[i][j]) = LOC(a[0][0]) + (j × m + i) × L

请特别留意：行优先的公式里出现的是列数 n，列优先的公式里出现的是行数 m。 这是最容易写错的地方，因为直觉上我们总觉得「求 (i,j) 的地址应该用到 i 前面的东西、乘上列数」， 但在列优先里，跨一整列要跨过的是 m 个元素。记忆口诀：行优先「乘列数」，列优先「乘行数」。

下面这段代码把两种排布都打印出来，可以直接对照上面两张图看：

#include <iostream>
using namespace std;

/* ============================================================
   二维数组的地址计算：行优先 vs 列优先
   设 A 是 m 行 n 列的二维数组，第一个元素 a[0][0] 的地址是 base，
   每个元素占 L 个字节（所有元素等长）。

   行优先 Row-Major（C / C++ / Java / Python 采用）：
       LOC(a[i][j]) = base + (i * n + j) * L
   列优先 Column-Major（Fortran / MATLAB 采用）：
       LOC(a[i][j]) = base + (j * m + i) * L
   ============================================================ */

long long rowMajorAddr(long long base, int n, int i, int j, int L) {
    return base + (1LL * i * n + j) * L;      /* 前面有 i 整行，本行再走 j 格 */
}

long long colMajorAddr(long long base, int m, int i, int j, int L) {
    return base + (1LL * j * m + i) * L;      /* 前面有 j 整列，本列再走 i 格 */
}

int main() {
    const int m = 3, n = 4, L = 4;            /* A[3][4]，每个 int 占 4 字节 */
    const long long base = 1000;              /* 假设 LOC(a[0][0]) = 1000 */

    cout << "A[3][4], base = " << base << ", L = " << L << "\n";

    cout << "row-major order: ";
    for (int i = 0; i < m; ++i)
        for (int j = 0; j < n; ++j)
            cout << "a[" << i << "][" << j << "]@" << rowMajorAddr(base, n, i, j, L) << "  ";
    cout << "\n";

    cout << "col-major order: ";
    for (int j = 0; j < n; ++j)
        for (int i = 0; i < m; ++i)
            cout << "a[" << i << "][" << j << "]@" << colMajorAddr(base, m, i, j, L) << "  ";
    cout << "\n";

    /* 单独验算 a[1][2]：行优先排在它前面的元素是 1*4+2 = 6 个 */
    cout << "a[1][2] row-major: (1*4+2)*4 = " << (1 * n + 2) * L
         << " bytes, addr = " << rowMajorAddr(base, n, 1, 2, L) << "\n";
    /* 列优先排在它前面的是 2*3+1 = 7 个 */
    cout << "a[1][2] col-major: (2*3+1)*4 = " << (2 * m + 1) * L
         << " bytes, addr = " << colMajorAddr(base, m, 1, 2, L) << "\n";

    /* 经典考题：题目不给首地址，只给某个元素的地址，问另一个元素的地址。
       做法是"只算偏移量之差"，base 会在相减时消掉。 */
    long long loc32 = rowMajorAddr(base, n, 3, 2, L);              /* 已知 a[3][2] 的地址 */
    long long delta = (1LL * 1 * n + 3) - (1LL * 3 * n + 2);       /* a[1][3] 与 a[3][2] 的元素序号差 */
    cout << "given a[3][2]@" << loc32 << ", a[1][3]@" << loc32 + delta * L
         << " (delta = " << delta << " elements)\n";
    return 0;
}
考点：谁来存第一个元素？ 教材上的公式常写成 LOC(a[i][j]) = LOC(a[0][0]) + (i×n+j)×L， 但考题里也可能给出 LOC(a[1][1]) 或者干脆只给 a[3][2] 的地址。 这时不要慌：先把你手上的已知点算成「线性下标」或者「元素序号」， 再做差值。首地址在相减时自然会被消掉：
LOC(a[i₂][j₂]) − LOC(a[i₁][j₁]) = [(i₂×n + j₂) − (i₁×n + j₁)] × L
这个「只算增量」的技巧适用于任何维数、任何优先顺序，是考场上的救命公式。

6.2.3 推广到 k 维数组：从最后一维开始递推

现在把二维的结论推广到 k 维。设数组是 d1 × d2 × … × dk， 下标记作 (i1, i2, …, ik)，各维下标都从 0 开始。 在行优先（最后一维变化最快）的约定下，线性序号是：

k线性 = i1·(d2d3…dk) + i2·(d3…dk) + … + ik−1·dk + ik
LOC = 首地址 + k线性 × L

这个公式不要死记，用递推（从最后一维往前套）的方式想，三秒钟就能重建出来：

  • 最后一维 ik 每加 1，就在内存里往后走 1 个元素，所以它的权重是 1；
  • 倒数第二维 ik−1 每加 1，意味着「把最后一维整段走完一遍」， 所以它的权重是 dk；
  • 再往前一维 ik−2 每加 1，意味着「把后面两维整块走完一遍」， 权重是 dk−1 × dk；
  • 依此类推，第 t 维的权重就是「它后面所有维度长度之积」。

用二维验证一下：d1=m, d2=n，则 i1 的权重是 d2 = n， i2 的权重是 1，于是 k = i×n + j，正是行优先公式，完全吻合。 如果换成列优先，规律反过来：第一维变化最快，所以第一维权重为 1，越靠前的维度权重越小。 

#include <iostream>
#include <vector>
using namespace std;

/* ============================================================
   k 维数组的行优先地址
   设数组是 d1 x d2 x ... x dk，下标 (i1, i2, ..., ik) 均从 0 开始，
   则线性序号（第几个元素）= i1*(d2*d3*...*dk) + i2*(d3*...*dk) + ... + ik
   LOC = base + 线性序号 * L

   递推理解：最后一维 ik 每走一步只跨 1 个元素；
             倒数第二维 i(k-1) 每走一步要跨 dk 个元素；
             再往前一层，每走一步跨 dk*d(k-1) 个……
             于是从最后一维开始往前"套"，就得到了上面的公式。
   ============================================================ */

long long kdLinearIndex(const vector<int>& dim, const vector<int>& idx) {
    long long lin = 0;
    for (size_t t = 0; t < dim.size(); ++t) {
        long long stride = 1;                       /* 第 t 维的步长 = 它后面所有维度的乘积 */
        for (size_t u = t + 1; u < dim.size(); ++u) stride *= dim[u];
        lin += 1LL * idx[t] * stride;
    }
    return lin;
}

/* 反向操作：已知线性序号，拆回各维下标（从最后一维往前取余、取商） */
vector<int> kdDecode(const vector<int>& dim, long long lin) {
    vector<int> idx(dim.size(), 0);
    for (size_t t = dim.size(); t-- > 0; ) {
        idx[t] = (int)(lin % dim[t]);
        lin /= dim[t];
    }
    return idx;
}

int main() {
    vector<int> dim = {3, 4, 5};                 /* 三维数组 A[3][4][5] */
    vector<int> idx = {1, 2, 3};                 /* 求 a[1][2][3] */
    const long long base = 1000, L = 4;

    long long lin = kdLinearIndex(dim, idx);
    cout << "A[3][4][5] a[1][2][3]: linear index = "
         << "1*(4*5) + 2*5 + 3 = " << lin << "\n";                 /* 20 + 10 + 3 = 33 */
    cout << "  LOC = " << base << " + " << lin << "*" << L << " = "
         << base + lin * L << "\n";                                /* 1132 */

    vector<int> back = kdDecode(dim, lin);
    cout << "decode(" << lin << ") = [" << back[0] << ", " << back[1]
         << ", " << back[2] << "]\n";

    /* 列优先（第一维变得最快）：线性序号 = i1 + i2*d1 + i3*d1*d2 */
    long long colLin = idx[0] + 1LL * idx[1] * dim[0] + 1LL * idx[2] * dim[0] * dim[1];
    cout << "a[1][2][3] col-major: 1 + 2*3 + 3*3*4 = " << colLin
         << ", LOC = " << base + colLin * L << "\n";               /* 43, 1172 */

    /* 相邻元素验证：把整块内存按行优先铺开，看看每个位置属于哪个下标 */
    cout << "row-major memory layout of A[2][3][2]:\n";
    vector<int> d2 = {2, 3, 2};
    for (long long p = 0; p < 2 * 3 * 2; ++p) {
        vector<int> ij = kdDecode(d2, p);
        cout << p << ":a[" << ij[0] << "][" << ij[1] << "][" << ij[2] << "]  ";
    }
    cout << "\n";
    return 0;
}

6.2.4 四道地址计算例题（务必自己先算一遍）

例 6-1 设二维数组 A[4][5]（4 行 5 列），每个元素占 4 个字节， LOC(a[0][0]) = 1000。求 a[2][3] 在行优先与列优先下的地址。

查看解答

行优先：先算线性下标，排在 a[2][3] 前面的元素有 2 整行 + 本行 3 个：

k = i × n + j = 2 × 5 + 3 = 13
LOC = 1000 + 13 × 4 = 1000 + 52 = 1052

列优先：这里「整块」是列，每列 4 个元素（行数 m = 4）：

k = j × m + i = 3 × 4 + 2 = 14
LOC = 1000 + 14 × 4 = 1000 + 56 = 1056

注意两者的差别只有 1 个元素（4 字节）——因为这两种排布在这里「恰好」很接近， 但千万不要以为它们总是一样，下一题就会拉开差距。

例 6-2 设 A[5][6] 按行优先存储，每个元素 2 字节， LOC(a[0][0]) = 2000。求 a[3][4] 与 a[4][5] 的地址， 并问：从 a[3][4] 到 a[4][5] 跨过了多少个元素？

查看解答
k(a[3][4]) = 3 × 6 + 4 = 22　⇒　LOC = 2000 + 22 × 2 = 2044
k(a[4][5]) = 4 × 6 + 5 = 29　⇒　LOC = 2000 + 29 × 2 = 2058

两者相差 29 − 22 = 7 个元素，共 14 字节。

另一种更快的算法：a[4][5] 只比 a[3][4] 靠后 「本行剩下的 1 个元素（列 5）+ 下一行的 6 个元素」= 7 个位置，与上面一致。 考场上用「数格子」验证公式，是最稳的习惯。

例 6-3 设三维数组 A[3][4][5]，每个元素 4 字节，LOC(a[0][0][0]) = 1000。 求 a[1][2][3] 在行优先下的地址；若改为列优先，地址又是多少？

查看解答

行优先（最后一维变化最快）：各维权重分别是 d2d3 = 4×5 = 20、 d3 = 5、1。

k = 1 × (4 × 5) + 2 × 5 + 3 = 20 + 10 + 3 = 33
LOC = 1000 + 33 × 4 = 1000 + 132 = 1132

列优先（第一维变化最快）：权重反过来， i1 权重 1、i2 权重 d1 = 3、 i3 权重 d1d2 = 12。

k = 1 × 1 + 2 × 3 + 3 × (3 × 4) = 1 + 6 + 36 = 43
LOC = 1000 + 43 × 4 = 1000 + 172 = 1172

怎么防止记混？记住一句话：哪个下标「变化最快」，它的权重就是 1； 权重沿着「慢 → 快」的方向依次乘以各维长度。

例 6-4 设二维数组 A[10][20] 按行优先存储，每个元素占 1 个字节。 已知 a[3][5] 的地址是 1010，求 a[5][8] 的地址。

查看解答

题目没有给首地址，这正是「只算增量」技巧的用武之地。设首地址为 base，则：

LOC(a[3][5]) = base + (3 × 20 + 5) × 1 = base + 65 = 1010 ⇒ base = 945
LOC(a[5][8]) = 945 + (5 × 20 + 8) × 1 = 945 + 108 = 1053

更快的写法（推荐）：直接算两个线性下标之差：

Δ = (5 × 20 + 8) − (3 × 20 + 5) = 108 − 65 = 43
LOC(a[5][8]) = 1010 + 43 × 1 = 1053

两种做法都对，但第二种不需要求 base，少一步、少一个出错点。 这类题在选择题里出现频率极高，务必练熟。

易错点集中营
  • 把行优先的 n 写成列优先的 m。再念一遍：行优先乘列数，列优先乘行数。
  • 下标从 0 开始还是从 1 开始没看清。本章统一使用 0 基下标（与 C/C++ 一致）。 如果题目声明「下标从 1 开始」，公式要改成 (i−1)×n + (j−1)。
  • 字节数 L 忘了乘。算出来的是「第几个元素」，题目问「地址」时必须再乘 L。
  • 三维数组照搬二维公式。三维必须老老实实按「权重 = 后面所有维度长度之积」来算。
  • 把 A[3][4] 当成「3 列 4 行」。A[m][n] 中 m 是行数、n 是列数， 这是约定，考试不会额外说明。

6.3 矩阵的压缩存储：压什么、怎么找回来

6.3.1 什么叫压缩存储

矩阵是数值计算的主角，一个 m × n 的矩阵用二维数组存下来要占 m × n × L 个字节。1000×1000 的 double 矩阵就是 8 MB， 听起来还行；但工程里动辄几十万阶的矩阵，直接开二维数组会瞬间把内存吃光。 于是我们自然会问：这些空间里，有多少是在存「废话」？

答案是很多。看几个例子：

  • 对称矩阵：a[i][j] = a[j][i]，以主对角线为轴的两半完全相同， 存两遍等于白白浪费一半空间。
  • 三角矩阵：主对角线的一侧全是同一个常数 c（常见于 c = 0）， 这一侧成千上万个格子存的都是同一个数。
  • 三对角（带状）矩阵：除了三条对角线，其余全是 0。n 阶矩阵有 n² 个格子， 真正有用的只有 3n−2 个。
  • 稀疏矩阵：非零元素极少（通常不到 5%），绝大多数格子是 0。

针对这些情况，教材给出了压缩存储的定义：

压缩存储（compressed storage） 为多个值相同的元素只分配一个存储空间，对零元素不分配存储空间。 例如对称矩阵只需要存下三角（含对角线）的 n(n+1)/2 个元素， 三角矩阵里的常数 c 只占一个单元，稀疏矩阵只存非零元。

这个定义里有两个关键词值得抠一抠。第一是「多个值相同的元素只分配一个空间」—— 注意它说的是「值相同」，而不是「位置相邻」。对称矩阵里 a[i][j] 与 a[j][i] 位置上离得很远，但值一定相同，于是我们可以只留一个。 第二是「零元素不分配空间」——注意这在数学上是有前提的： 只有当「0 是这批数据的默认值」时，不存 0 才能靠「没存的就是 0」把信息补回来。 如果矩阵里 0 和别的数一样是「有意义的数据」，那就不能这么干。

6.3.2 压缩的前提：元素分布必须有规律

压缩存储不是变魔术，它必须付出代价。代价是什么？是「要知道某个位置的元素在哪里， 得先算一算」。而这个「算」能不能在 O(1) 时间内完成， 完全取决于元素分布的规律性。

✅ 有规律，可以压缩

  • 对称矩阵：非零（不重复）区域由 i ≥ j 严格刻画。
  • 三角矩阵：常数区由 i < j 或 i > j 刻画。
  • 带状矩阵：非零区由 |i − j| ≤ b 刻画。
  • 共同点：「哪些元素要存」可以用下标的不等式写出来， 于是「前面有多少个元素」可以用等差数列求和算出来。

❌ 没规律，只能换一种存法

  • 一般稀疏矩阵：零元素东一个西一个，位置随机，规律是「没有规律」。
  • 既然无法用不等式描述，就无法用公式计算位置。
  • 退而求其次：把「位置」也一起存下来，即存成 (行号, 列号, 值) 三元组。
  • 代价：每个非零元多了两个整数的开销，而且随机存取能力通常保不住。

所以「压缩存储」实际上分成两大流派： 公式法（顺序存储 + 下标映射）用于对称 / 三角 / 带状这类结构规整的矩阵； 列表法（三元组 / 链表）用于稀疏矩阵。前者能保住 O(1) 随机存取， 后者不能。这也正是本章 6.4–6.6 与 6.7 的分界线。

6.3.3 下标映射函数：压缩存储的灵魂

压缩之后，原来的二维下标 (i, j) 不再等于内存位置，我们需要一个函数把它翻译过去：

k = f(i, j)　（二维下标 → 一维数组下标）

这个 f 就叫下标映射函数（index mapping function）。有了它， get(i,j) 就是 sa[f(i,j)]，set(i,j,v) 就是 sa[f(i,j)] = v，两条语句、常数时间。整个压缩存储方案的价值， 全都压在这个函数身上。

好消息是：所有这类函数的推导套路都是同一套三步法，掌握之后可以临场推、不用背：

  1. 第一步：确定「存哪些」。画出矩阵，把要存的区域涂上颜色， 用下标不等式描述它（比如对称矩阵存 i ≥ j）。 顺便数一数总共有多少个元素，得到数组长度。
  2. 第二步：确定「按什么顺序存」。绝大多数教材用行优先： 先存第 0 行里要存的那些，再存第 1 行……这一步决定了「整块」是行还是列。
  3. 第三步：数「排在 (i,j) 前面的元素有多少个」。 把它拆成「前面完整的若干行」+「本行内排在它前面的几个」， 前者是一个等差数列求和，后者往往就是几。加在一起就是 k。
第三步的万能公式
k = （前 i 行要存的元素总数）+ （第 i 行内排在 j 前面的元素个数）
只要「每行要存的元素个数」构成等差数列，「前 i 行总数」就能一步算出来。 对称矩阵每行存 1,2,3,…,n 个（公差 1），三对角矩阵每行存 2,3,3,…,3,2 个 （中间公差 0，首尾特殊），这就是它们公式长得不一样的根本原因。

6.3.4 压完之后还能随机存取吗

这是考试里最爱问的辨析题，答案要看「f 能不能 O(1) 算出来」：

矩阵类型压缩方式按下标取值原因
对称矩阵下三角压进一维数组 保留 O(1) k = i(i+1)/2 + j 是闭式公式，一次乘加即可
三角矩阵三角区 + 一个常数单元 保留 O(1) 常数区直接返回 c，非常数区用公式
三对角矩阵三条对角线压进一维数组 保留 O(1) k = 2i + j；带外元素直接返回 0
稀疏矩阵三元组顺序表（按行有序） 不保留 要找到 (i,j) 得顺序查找，最坏 O(tu)； 若再建 rpos[]，可先定位行、再在行内查找
十字链表 不保留（但很好用） 可从 rhead[i] 沿 right 找，代价与行内非零元个数成正比
CSR（行压缩） 部分保留 按行访问 O(该行 nnz)；直接按 (i,j) 定位仍需行内二分或哈希

一句话总结：压缩存储是否保留随机存取，取决于压缩后「位置信息」是否被一个 O(1) 可算的公式完整保留下来。对称 / 三角 / 带状矩阵的规律是「全局的」， 一个公式管全部；稀疏矩阵的规律是「局部的」，只能靠额外的索引结构（rpos[]、 十字链表、哈希）去补救。

6.4 对称矩阵的压缩存储

6.4.1 定义与压缩方案

设 A 是 n 阶方阵，如果对所有 0 ≤ i, j ≤ n−1 都有

a[i][j] = a[j][i]

则称 A 为对称矩阵（symmetric matrix）。它是沿主对角线「照镜子」左右对称的， 所以只要知道一半，另一半就全知道了。

压缩方案的选择很自然：只存下三角（含主对角线），按行优先顺序 压进一个一维数组 sa[]。为什么不存上三角？纯粹是习惯—— 教材和考试统一按下三角来，你跟着来就行（存上三角也完全可以，公式对称地改一下即可）。

为什么是「含主对角线」？因为对角线上的元素 a[i][i] 满足 i = j， 它在镜子上的像是它自己，只存一次正好，丢掉就再也找不回来了。

6.4.2 下标映射公式的完整推导

现在按 6.3.3 的三步法，把 k = f(i, j) 推出来。这一段请务必跟着算一遍， 它是本章所有公式的模板。

第一步：存哪些？共多少个？

存下三角（含对角线），即所有满足 i ≥ j 的元素。数一数每行有几个： 第 0 行有 1 个（a[0][0]），第 1 行有 2 个（a[1][0], a[1][1]）， …，第 i 行有 i+1 个，…，第 n−1 行有 n 个。 总数是一个等差数列之和：

总数 = 1 + 2 + 3 + … + n

用等差数列求和公式（首项 + 末项）× 项数 ÷ 2：

S = (1 + n) × n / 2 = n(n+1)/2

所以一维数组 sa[] 的长度是 n(n+1)/2， 下标范围是 0 … n(n+1)/2 − 1。 例如 n = 5 时长度是 5×6/2 = 15，与图 6-5 一致。 （顺带记一个常用结论：1+2+…+i = i(i+1)/2， 这个「三角形数」在后面反复出现，是本章最常用的求和式。）

第二步：按什么顺序存？

按行优先——先把第 0 行里要存的元素从左到右放好，再放第 1 行的，依此类推。 于是在一维数组里，第 0 行占据 sa[0..0]， 第 1 行占据 sa[1..2]，第 2 行占据 sa[3..5]， 第 i 行占据 sa[i(i+1)/2 .. i(i+1)/2 + i]。 这正是图 6-5 右边那个「阶梯」形状的来历。

第三步：数一数 (i, j) 前面有多少个元素。

分两种情况讨论。

情况 A：i ≥ j（元素本来就在下三角里，值就存在 sa 中）。 排在它前面的元素由两部分组成：

  • 第 0 行到第 i−1 行是完整的 i 行， 每行的元素个数分别是 1, 2, …, i， 共 1 + 2 + … + i = i(i+1)/2 个；
  • 在它自己所在的第 i 行里，列号从 0 数到 j−1， 共 j 个元素（注意：是 j 个，不是 j+1 个， 因为 a[i][j] 自己不算「排在前面」）。

两部分相加：

k = i(i+1)/2 + j　　（当 i ≥ j）

情况 B：i < j（元素在上三角，本身不存储）。 由对称性 a[i][j] = a[j][i]，而 (j, i) 满足 j > i， 即 j ≥ i，一定落在下三角里（含对角线），可以直接套用情况 A 的公式， 只要把 i 和 j 的角色对调：

k = j(j+1)/2 + i　　（当 i < j）

把两个式子合起来写，就是对称矩阵的下标映射函数：

f(i, j) = i(i+1)/2 + j　(i ≥ j)　；　f(i, j) = j(j+1)/2 + i　(i < j)
用几个小数据自检
  • f(0,0) = 0×1/2 + 0 = 0 ✅ 第一个元素当然在 0 号位。
  • f(1,0) = 1×2/2 + 0 = 1 ✅ 第 1 行的第一个。
  • f(1,1) = 1 + 1 = 2 ✅ 第 1 行的第二个。
  • f(2,0) = 2×3/2 + 0 = 3 ✅ 前面正好装下第 0、1 行的 1+2 = 3 个。
  • f(i, i) = i(i+1)/2 + i = i(i+3)/2，正好是第 i 行的最后一个位置， 也是前 i+1 行的总数 (i+1)(i+2)/2 − 1，两者相等 ✅
自己动手代几个数，比背十遍公式都管用。

6.4.3 两道手算例题

例 6-5 n = 5 的对称矩阵按「下三角 + 行优先」压缩进一维数组 sa[]， 问 a[3][1] 与 a[1][3] 分别存在 sa 的哪个位置？ 数组总长是多少？

查看解答

求 a[3][1]：此时 i = 3, j = 1，满足 i ≥ j，用情况 A：

k = i(i+1)/2 + j = 3 × 4 / 2 + 1 = 6 + 1 = 7

求 a[1][3]：此时 i = 1, j = 3，满足 i < j，用情况 B （本质上就是去查 a[3][1]）：

k = j(j+1)/2 + i = 3 × 4 / 2 + 1 = 6 + 1 = 7

两者当然相同——因为它们本来就是同一个值，压缩存储后共用 sa[7] 这一个单元。

数组总长：n(n+1)/2 = 5 × 6 / 2 = 15，合法下标 0 ~ 14。

验证：数一数 sa[7] 的位置——第 0 行 1 个、第 1 行 2 个、第 2 行 3 个， 共 6 个占掉 sa[0..5]；第 3 行从 sa[6] 开始， sa[6] = a[3][0]、sa[7] = a[3][1] ✅ 完全吻合。

例 6-6 n = 6 的对称矩阵压缩后，a[5][5]、a[2][5]、 a[4][2] 分别存在哪里？一维数组最大下标是多少？

查看解答

数组长度 6 × 7 / 2 = 21，最大下标 20。

a[5][5]（i = j = 5，下三角，是最后一行最后一个元素）：

k = 5 × 6 / 2 + 5 = 15 + 5 = 20 ✅ 正好是最大下标，逻辑自洽。

a[2][5]（i = 2 < j = 5，上三角，转成 a[5][2]）：

k = j(j+1)/2 + i = 5 × 6 / 2 + 2 = 15 + 2 = 17

a[4][2]（i = 4 ≥ j = 2，下三角）：

k = 4 × 5 / 2 + 2 = 10 + 2 = 12

反向检查：第 4 行从 k = 4×5/2 = 10 开始， sa[10] = a[4][0]、sa[11] = a[4][1]、 sa[12] = a[4][2] ✅ 正确。

例 6-7（反向题） 一个 6 阶对称矩阵压缩后得到 sa[0..20]。已知某个值存在 sa[12]， 它在原矩阵中的下标 (i, j) 是什么（只写下三角的那个）？

查看解答

反向题的思路是「找行首」：第 i 行的第一个元素在 i(i+1)/2， 我们要找到一个 i，使得

i(i+1)/2 ≤ 12 < (i+1)(i+2)/2

逐个试：i = 4 时左边是 4×5/2 = 10 ≤ 12； i = 5 时左边是 5×6/2 = 15 > 12，停。

所以它在第 4 行，行内偏移 j = 12 − 10 = 2， 即 sa[12] 存的是 a[4][2]（也就等于 a[2][4]）。

这类「由 k 反求 (i, j)」的题在填空题里很常见，操作上就是一次简单的试根， 熟悉后可以心算：√(2k) 附近找一找就行。

6.4.4 C++ 实现：全局数组 + 下标映射函数

把公式写进代码只有两行的事。竞赛里的写法非常直接：开一个全局数组 sa[]，再写一个 idx(i, j) 把二维下标映射成一维下标， 存取各写一个自由函数就行——不封类、不模板、不抛异常，代码能在考场上三分钟敲完。 要注意的只有两点：下标越界的检查（越界只提示、不崩溃）和 映射函数要单独写出来，方便和手算的 k 对照。 

#include <bits/stdc++.h>
using namespace std;

/* ============================================================
   对称矩阵的压缩存储（竞赛写法：全局数组 + 下标映射函数）
   定义：n 阶方阵 A 满足 a[i][j] == a[j][i]，只需存下三角（含对角线）。

   按行优先把下三角压进一维数组 sa[0 .. n(n+1)/2 - 1]：
       i >= j （下三角）：k = i*(i+1)/2 + j
       i <  j （上三角）：k = j*(j+1)/2 + i     （利用 a[i][j] = a[j][i]）

   存储长度 1 + 2 + ... + n = n(n+1)/2，比原来的 n^2 省了近一半。
   例如 n = 5：长度 15，a[3][1] 与 a[1][3] 都映射到 k = 7，共用同一个单元。
   ============================================================ */

const int N  = 1005;                  /* 最大阶数 */
const int SA = N * (N + 1) / 2;       /* 一维数组长度：n(n+1)/2 个单元 */
int sa[SA];                           /* 压缩数组：行优先存下三角（含对角线） */
int n;                                /* 矩阵阶数 */

/* 下标映射函数：把二维下标 (i, j) 映射成一维下标 k
   下三角：前面有 i 整行共 1+2+...+i = i(i+1)/2 个元素，本行再走 j 格
   上三角：换成对称位置 (j, i) 套同一个公式 —— 「对称性免费」就是这么来的 */
inline int idx(int i, int j) {
    return (i >= j) ? (i * (i + 1) / 2 + j)      /* 下三角 */
                    : (j * (j + 1) / 2 + i);     /* 上三角 */
}

/* 边界检查：竞赛里不抛异常，越界就打印提示并拒绝这次操作 */
bool inRange(int i, int j) {
    if (0 <= i && i < n && 0 <= j && j < n) return true;
    printf("  [warn] (%d, %d) out of range\n", i, j);
    return false;
}

/* 存：只需写一次，对称位置「自动」也是同一个值 */
void setVal(int i, int j, int v) {
    if (!inRange(i, j)) return;
    sa[idx(i, j)] = v;
}

/* 取：上、下三角走同一套映射，O(1)（一次乘法 + 一次加法） */
int getVal(int i, int j) {
    if (!inRange(i, j)) return 0;
    return sa[idx(i, j)];
}

/* 打印整个一维数组，方便与手算结果对照 */
void dump() {
    int len = n * (n + 1) / 2;
    for (int k = 0; k < len; ++k) printf("%d%c", sa[k], k + 1 == len ? '\n' : ' ');
}

/* 函数名为什么叫 setVal 而不是 set？
   using namespace std 之后，自由函数 set 会和 std::set 撞名，
   g++ 直接报 "reference to 'set' is ambiguous"，所以换个名字。 */

int main() {
    n = 5;
    printf("n = %d, storage size = %d (n(n+1)/2 = %d)\n",
           n, n * (n + 1) / 2, n * (n + 1) / 2);          /* 15 */

    /* 手算例题：n = 5 时 a[3][1] 与 a[1][3] 存在哪个位置？ */
    printf("a[3][1] -> k = %d\n", idx(3, 1));             /* 3*4/2+1 = 7 */
    printf("a[1][3] -> k = %d\n", idx(1, 3));             /* 3*4/2+1 = 7 */

    /* 按下三角的行优先顺序填入 1,2,3,...，再打印一维数组对照 */
    int val = 0;
    for (int i = 0; i < n; ++i)
        for (int j = 0; j <= i; ++j)
            setVal(i, j, ++val);
    printf("sa[] = ");
    dump();                                               /* 1 2 3 ... 15 */

    /* 验证对称性：任意 (i,j) 都有 getVal(i,j) == getVal(j,i) */
    bool ok = true;
    for (int i = 0; i < n; ++i)
        for (int j = 0; j < n; ++j)
            if (getVal(i, j) != getVal(j, i)) ok = false;
    printf("symmetry check: %s\n", ok ? "PASS" : "FAIL");

    /* 写一次 a[3][1]，读 a[1][3] 也是同一个值：两次访问命中同一个内存单元 */
    setVal(3, 1, 41);
    printf("set a[3][1] = 41, then a[1][3] = %d\n", getVal(1, 3));   /* 41 */

    /* 边界检查：越界只提示、不崩溃 */
    printf("a[5][0] = %d  (out of range)\n", getVal(5, 0));
    return 0;
}

这段代码里有三个细节值得单独说：

  • idx(i, j) 用 (i >= j) ? ... : ... 一次搞定上下三角， 这就是公式的直接翻译。它只需要一次乘法和一次加法，所以 getVal/setVal 是 O(1)——对称矩阵压缩后随机存取能力完好无损。
  • setVal(3,1,41) 之后 getVal(1,3) 也是 41，这不是巧合， 而是因为 idx(3,1) 与 idx(1,3) 都等于 7， 两次访问命中同一个内存单元。「对称性」在压缩存储里是免费的。
  • 数组开成全局的 sa[N*(N+1)/2]：竞赛里数组开够就不再动态申请内存， 程序结束由操作系统统一回收，不写 new/delete，也不写析构函数。 代价是长度上限写死在 N 里，做题时按题目数据范围开即可。
  • 写函数时别取名 set：using namespace std 之后它会和 std::set 撞名，g++ 直接报 reference to 'set' is ambiguous， 所以这里叫 setVal（同理 getVal，避免和 std::get 混淆）。

6.5 三角矩阵的压缩存储

6.5.1 两种三角矩阵与压缩方案

三角矩阵（triangular matrix）分两种，定义只差一个方向：

下三角矩阵（lower triangular）
主对角线以上（不含主对角线）的元素全是同一个常数 c， 即当 i < j 时恒有 a[i][j] = c。 主对角线及以下的部分是「真实数据」。
上三角矩阵（upper triangular）
主对角线以下（不含主对角线）的元素全是同一个常数 c， 即当 i > j 时恒有 a[i][j] = c。

注意定义里那句「不含主对角线」——对角线永远是真实数据，必须老老实实存下来。 最常见的常数是 c = 0（例如高斯消元过程中出现的上三角方程组系数矩阵）， 但定义本身对 c 没有限制，所以我们的方案必须能存下任意常数。

压缩方案与对称矩阵几乎一样（两种矩阵的对照见图 6-6），只有一处不同：

  1. 把真实数据区（下三角或上三角，含对角线）按行优先压进 sa[0 … n(n+1)/2 − 1]，共 n(n+1)/2 个单元；
  2. 常数 c 单独占用最后一个单元 sa[n(n+1)/2]。

所以三角矩阵的压缩数组长度是 n(n+1)/2 + 1。 为什么常数区已经「全都一样」了，还要单独留一个位置？因为「全都一样」不等于 「等于多少已知」。对称矩阵的上三角可以靠 a[j][i] 推算出来， 而三角矩阵的常数区推算不出来，必须把 c 的值存一份。 （如果题目明确说了 c = 0，实现时当然可以省掉这个单元， 但考试里请按通式 +1 回答。）

6.5.2 下三角矩阵：公式与长度

下三角矩阵要存的部分正好是 i ≥ j，和对称矩阵存的区域一模一样， 所以下标公式也一模一样：

k = i(i+1)/2 + j　（i ≥ j，即在下三角内）

唯一的区别出在 i < j 的时候：对称矩阵会「照镜子」去查 a[j][i]， 而下三角矩阵里这些位置的值是常数 c，直接返回 sa[n(n+1)/2] 即可。 写成代码就是一句话：

k = (i >= j) ? (i*(i+1)/2 + j) : (n*(n+1)/2)

数组长度 n(n+1)/2 + 1：前 n(n+1)/2 个单元放真实数据， 最后 1 个单元放常数。

6.5.3 上三角矩阵：公式推导

上三角矩阵的推导要用到 6.3.3 的同一个套路，只是「每行有几个元素」不再是 1,2,3,…， 而是递减的：

第一步：存哪些、共多少个？

按行优先存 i ≤ j 的部分。第 i 行要存的是 j = i, i+1, …, n−1，个数是 n − i。 于是各行个数依次是 n, n−1, n−2, …, 1，总数仍是

n + (n−1) + … + 1 = n(n+1)/2　（与下三角一样多，只是顺序反过来）

第二步：按行优先存。第 i 行的起点是「前 i 行的总数」。

第三步：数 (i, j) 前面有多少个元素。分成两块：

  • 前 i 行的总数：n + (n−1) + … + (n−i+1)。 这是一个首项为 n、末项为 n−i+1、共 i 项的等差数列， 用「(首项 + 末项) × 项数 ÷ 2」：
    (n + (n−i+1)) × i / 2 = i(2n − i + 1)/2
    （也可以用另一种算法验证：Σt=0i−1(n−t) = i·n − i(i−1)/2， 通分后是 (2in − i² + i)/2 = i(2n−i+1)/2，两式一致 ✅）
  • 本行内排在 j 前面的个数：本行从列号 i 开始放， 放到 j 之前一共放了 j − i 个。

两式相加，得到上三角矩阵的下标映射函数：

k = i(2n − i + 1)/2 + (j − i)　（i ≤ j）

当 i > j 时，元素落在常数区，k = n(n+1)/2。 数组长度同样是 n(n+1)/2 + 1。

公式自检（n = 5）
  • f(0,0) = 0×11/2 + 0 = 0 ✅ 第 0 行第 1 个。
  • f(0,4) = 0 + 4 = 4 ✅ 第 0 行有 5 个元素，占 sa[0..4]，最后一个正是它。
  • f(1,1) = 1×(10−1+1)/2 + 0 = 5 ✅ 第 1 行从 sa[5] 开始。
  • f(4,4) = 4×(10−4+1)/2 + 0 = 4×7/2 = 14 ✅ 15 个真实数据的最后一个，正好是 sa[14]。
注意那个 i(2n−i+1)/2 里的乘积一定是偶数（i 为偶数时显然； i 为奇数时 2n−i+1 必为偶数），所以整数除法不会丢精度。

6.5.4 两道手算例题

例 6-8 n = 5 的下三角矩阵（常数 c = 0）按行优先压缩， 求 a[3][2]、a[4][4]、a[0][4] 的存储位置， 以及数组总长度。

查看解答

数组长度 n(n+1)/2 + 1 = 15 + 1 = 16，常数 c 存在 sa[15]。

a[3][2]：i=3 ≥ j=2 ⇒ k = 3×4/2 + 2 = 6 + 2 = 8
a[4][4]：i=4 ≥ j=4 ⇒ k = 4×5/2 + 4 = 10 + 4 = 14（最后一个真实数据）
a[0][4]：i=0 < j=4 ⇒ 落在常数区 ⇒ k = 15，值就是 c

检查：第 4 行从 k = 4×5/2 = 10 开始，本行有 5 个元素 （sa[10] ~ sa[14]），刚好把 15 个数据位用完，常数单元 sa[15] 紧随其后 ✅

例 6-9 同样 n = 5，但换成上三角矩阵（常数 c = 0）。 求 a[1][3]、a[0][4]、a[4][4]、a[3][1] 的位置。

查看解答

上三角公式：k = i(2n−i+1)/2 + (j−i)，其中 n = 5，故 2n+1 = 11。

a[1][3]：k = 1×(10−1+1)/2 + (3−1) = 5 + 2 = 7
a[0][4]：k = 0×11/2 + 4 = 4
a[4][4]：k = 4×(10−4+1)/2 + 0 = 14 + 0 = 14
a[3][1]：i=3 > j=1 ⇒ 落在常数区 ⇒ k = 15

用「数格子」验证 a[1][3]：第 0 行有 5 个（sa[0..4]）， 第 1 行从 sa[5] 开始放 a[1][1], a[1][2], a[1][3], a[1][4]， 于是 a[1][1]→5、a[1][2]→6、a[1][3]→7 ✅ 与公式一致。

易错：上三角的公式里那个「j − i」 很多人会顺手写成 k = i(2n−i+1)/2 + j，那就错了。 因为第 i 行是从列 i 开始存的，a[i][i] 才是这一行的第一个， 所以行内偏移必须是 j − i 而不是 j。 下三角之所以不用减，是因为第 i 行确实从列 0 开始存。
记忆方法：「上三角每行起步晚，要减掉起步的 i」。

6.5.5 C++ 实现：两套映射函数与边界检查

下三角与上三角各给一套映射函数（lowIdx / upIdx）和两个数组 （saL[] / saU[]）。除了公式本身，请重点看边界检查是怎么做的： 下标越界要提示；往常数区写一个不等于 c 的值，也要立刻报错（这里用返回 false 表示拒绝）——因为那说明调用者的逻辑已经错了，静默接受只会让 bug 藏得更深。 竞赛代码不抛异常，用返回值或打印提示来表达「这次操作不合法」，一样能起到暴露错误的作用。 

#include <bits/stdc++.h>
using namespace std;

/* ============================================================
   三角矩阵的压缩存储（竞赛写法：两套映射函数 + 常数单元单独存）
   ------------------------------------------------------------
   下三角矩阵：主对角线以上（不含对角线）的元素全是同一个常数 c
       存法：saL[0 .. n(n+1)/2 - 1] 按下三角行优先存；
             saL[n(n+1)/2] 单独存常数 c。
       i >= j : k = i*(i+1)/2 + j
       i <  j : k = n(n+1)/2             （常数单元）
       数组长度 n(n+1)/2 + 1

   上三角矩阵：主对角线以下（不含对角线）的元素全是同一个常数 c
       存法：按行优先存上三角，第 i 行存 j = i .. n-1，共 n-i 个元素；
             前 i 行共 sum_{t=0}^{i-1}(n-t) = i*n - i(i-1)/2 = i(2n-i+1)/2 个元素。
             注意第 i 行是从列 i 开始存的，所以行内偏移是 (j-i) 而不是 j。
       i <= j : k = i*(2n-i+1)/2 + (j-i)
       i >  j : k = n(n+1)/2
       数组长度同样 n(n+1)/2 + 1
   ============================================================ */

const int N  = 1005;                  /* 最大阶数 */
const int SA = N * (N + 1) / 2 + 1;   /* 长度：n(n+1)/2 个真实数据 + 1 个常数单元 */
int saL[SA];                          /* 下三角矩阵的压缩数组 */
int saU[SA];                          /* 上三角矩阵的压缩数组 */
int n;                                /* 阶数 */
int cst;                              /* 常数 c */

/* 常数单元的下标：下三角、上三角都是 n(n+1)/2 这一格 */
inline int constIdx() { return n * (n + 1) / 2; }

/* 下三角映射（i >= j 时有效）：k = i*(i+1)/2 + j */
inline int lowIdx(int i, int j) { return i * (i + 1) / 2 + j; }

/* 上三角映射（i <= j 时有效）：k = i*(2n-i+1)/2 + (j-i) */
inline int upIdx(int i, int j) { return i * (2 * n - i + 1) / 2 + (j - i); }

/* 边界检查：竞赛里不抛异常，越界就返回 false 让调用者自己处理 */
bool inRange(int i, int j) {
    if (0 <= i && i < n && 0 <= j && j < n) return true;
    printf("  [warn] (%d, %d) out of range\n", i, j);
    return false;
}

/* 初始化：把两个数组的常数单元都预置成 c，
   这样即使从没写过常数区，读出来的也是正确的 c */
void init(int nn, int c) {
    n = nn; cst = c;
    for (int k = 0; k <= constIdx(); ++k) { saL[k] = c; saU[k] = c; }
}

/* ---------- 下三角 ---------- */
/* 存：i >= j 写真实位置；i < j 落在常数区，只允许写 c */
bool lowSet(int i, int j, int v) {
    if (!inRange(i, j)) return false;
    if (i < j) {                     /* 这一类位置压缩后根本没有独立存储单元 */
        if (v != cst) {
            printf("  [warn] a[%d][%d] 在常数区，只能写 c = %d\n", i, j, cst);
            return false;            /* 静默接受只会让 bug 藏得更深 */
        }
        return true;                 /* 写的就是 c，等于没写 */
    }
    saL[lowIdx(i, j)] = v;
    return true;
}
int lowGet(int i, int j) {
    if (!inRange(i, j)) return 0;
    return i >= j ? saL[lowIdx(i, j)] : saL[constIdx()];
}

/* ---------- 上三角 ---------- */
bool upSet(int i, int j, int v) {
    if (!inRange(i, j)) return false;
    if (i > j) {                     /* 常数区 */
        if (v != cst) {
            printf("  [warn] a[%d][%d] 在常数区，只能写 c = %d\n", i, j, cst);
            return false;
        }
        return true;
    }
    saU[upIdx(i, j)] = v;
    return true;
}
int upGet(int i, int j) {
    if (!inRange(i, j)) return 0;
    return i <= j ? saU[upIdx(i, j)] : saU[constIdx()];
}

int main() {
    init(5, 0);                                            /* n = 5，常数 c = 0 */

    lowSet(3, 2, 7);
    lowSet(4, 4, 9);
    printf("lower triangular, n = %d\n", n);
    printf("  a[3][2] = %d, k = %d   (3*4/2 + 2 = 8)\n", lowGet(3, 2), lowIdx(3, 2));
    printf("  a[4][4] = %d, k = %d  (4*5/2 + 4 = 14)\n", lowGet(4, 4), lowIdx(4, 4));
    printf("  a[0][4] = %d, k = %d  (constant cell)\n", lowGet(0, 4), constIdx());
    printf("  storage size = %d = n(n+1)/2 + 1 = %d\n",
           constIdx() + 1, n * (n + 1) / 2 + 1);           /* 16 */

    upSet(1, 3, 5);
    upSet(0, 4, 6);
    printf("upper triangular, n = %d\n", n);
    printf("  a[1][3] = %d, k = %d   (1*(10-1+1)/2 + 2 = 7)\n", upGet(1, 3), upIdx(1, 3));
    printf("  a[0][4] = %d, k = %d   (0*11/2 + 4 = 4)\n", upGet(0, 4), upIdx(0, 4));
    printf("  a[4][4] = %d, k = %d  (4*(10-4+1)/2 + 0 = 14)\n", upGet(4, 4), upIdx(4, 4));
    printf("  a[4][0] = %d  (constant cell)\n", upGet(4, 0));
    printf("  storage size = %d\n", constIdx() + 1);

    /* 边界检查：越界、以及「往常数区写非 c 值」都应该被拦住 */
    printf("lowGet(5, 0)      -> %d\n", lowGet(5, 0));
    printf("lowSet(0, 4, 1)   -> %s\n", lowSet(0, 4, 1) ? "true" : "false");
    return 0;
}

三个要点：

  • inRange(i, j) 负责越界检查。竞赛里不用 throw std::out_of_range 那套异常机制（考场上没人写 try/catch），而是打印一行提示并拒绝这次操作： 越界属于调用者的编程错误，必须立刻看得见；打印出来的 warning 就是最直接的暴露方式。
  • lowSet(i, j, v) 在 i < j（下三角的常数区）时， 如果 v != cst 直接返回 false： 这一类位置在压缩后根本没有独立的存储单元，允许写入不同值会让数据结构自相矛盾。
  • init(n, c) 把两个数组的常数单元都预置成 c （位置就是 saL[n(n+1)/2] / saU[n(n+1)/2]）， 这样即使从没写过常数区，读出来的也是正确的 c—— 这就是「三角矩阵要比对称矩阵多存一个单元」的那一格。

6.6 对角矩阵（带状矩阵）的压缩存储

6.6.1 三对角矩阵的定义

如果矩阵中所有非零元素都集中在主对角线附近的若干条对角线上，就称它为 带状矩阵（band matrix），集中分布的这些对角线构成「带」。 最常见的是三对角矩阵（tridiagonal matrix），也叫带宽为 3 的带状矩阵：

当 |i − j| ≤ 1 时 a[i][j] 可能非零；当 |i − j| > 1 时 a[i][j] = 0

三条对角线各有名字：i = j 是主对角线，j = i + 1 是主对角线 上方的第一条，i = j + 1 是主对角线下方的第一条。 三对角矩阵在数值计算里出现的频率高得惊人：三次样条插值、一维热传导方程的差分格式、 隐式求解偏微分方程，最后都会归结为「解一个三对角线性方程组」， 而这类方程组可以用追赶法（Thomas 算法）在 O(n) 时间内解出—— 前提正是它被压缩存储了。

一个 n 阶三对角矩阵有 n² 个元素，但真正可能非零的只有多少？ 数一数：第 0 行 2 个；中间第 1 … n−2 行每行 3 个；最后一行 2 个。于是

2 + 3(n − 2) + 2 = 3n − 2

例如 n = 1000 时，n² = 1000000 而 3n − 2 = 2998， 压缩率高达 99.7%。这就是压缩存储的威力。

6.6.2 下标公式的推导与长度 3n−2

还是那三步。这次「每行存几个」不再是等差的了，所以要分情况。

第一步：每行存几个？

  • 第 0 行：只有 a[0][0] 和 a[0][1]，共 2 个 （a[0][−1] 不存在）；
  • 第 i 行（1 ≤ i ≤ n−2）：a[i][i−1], a[i][i], a[i][i+1]，共 3 个；
  • 第 n−1 行：a[n−1][n−2] 和 a[n−1][n−1]，共 2 个。

总数：

2 + 3 × (n − 2) + 2 = 2 + 3n − 6 + 2 = 3n − 2

于是压缩数组 sa[] 的长度是 3n − 2，下标范围 0 … 3n−3。 n = 5 时是 13，n = 6 时是 16（与图 6-7 一致）。

第二步与第三步：算 k。

情况 1：i = 0。第 0 行前面什么都没有，本行从列 0 开始放， 所以行内偏移就是 j：

k = j　（i = 0，j = 0 或 1）

情况 2：i ≥ 1。前 i 行（第 0 行到第 i−1 行）的元素总数是 「第 0 行的 2 个 + 中间 (i−1) 行每行 3 个」：

前 i 行总数 = 2 + 3(i − 1) = 3i − 1

第 i 行是从列 i−1 开始放的（因为第一个元素是 a[i][i−1]）， 所以 a[i][j] 在本行内是第 j − (i−1) = j − i + 1 个元素， 行内偏移就是 j − i + 1。两者相加：

k = (3i − 1) + (j − i + 1) = 3i − 1 + j − i + 1 = 2i + j

有意思的是，i = 0 时 2i + j = j，与情况 1 的结果完全一致。 所以两种写法可以统一成一个式子：

k = 2i + j　（只要 |i − j| ≤ 1）

为什么能统一？因为第 0 行「少的那一个元素」正好被 3i − 1 在 i = 0 时 多减的 1 抵消掉了。这也解释了一个容易困惑的点：这个统一公式只在带内成立， 带外的 (i, j) 代进去会算出越界的 k（比如 a[0][5] 会算出 5， 而它其实应该是 0），所以实现时必须先判断 |i − j| ≤ 1。

反向映射（由 k 求 i, j）。把 k = 2i + j 与 j − i ∈ {−1, 0, 1} 联立，可以得到一个漂亮的闭式：

i = ⌊(k + 1) / 3⌋　（向下取整）　，　j = k − 2i

验证：k = 0 → i = 0, j = 0；k = 2 → i = 1, j = 0； k = 6 → i = 2, j = 2；k = 12 → i = 4, j = 4 ✅ 这条公式在「已知某个一维下标，反求它在矩阵中的位置」这类题里非常好用。

考点：另一种常见的带状存法 B[3][n] 有些教材（尤其是数值计算方向）不用一维数组，而是用一个 3 × n 的二维数组 B 按「对角线」来存：
B[0][j] = a[j−1][j]（上方那条对角线），B[1][j] = a[j][j]（主对角线），B[2][j] = a[j+1][j]（下方那条对角线）
于是 a[i][j] = B[j − i + 1][j]（要求 |i−j| ≤ 1）。 这种存法一共 3n 个单元，比分情况压平的 3n − 2 多 2 个 （四个角上浪费了）。两种做法都正确，考试时看清题目要求的是哪一种： 问「数组长度」时，3n − 2 与 3n 是两个不同的答案。

6.6.4 C++ 实现，以及「为什么还能 O(1)」

#include <bits/stdc++.h>
using namespace std;

/* ============================================================
   三对角（带状）矩阵的压缩存储（竞赛写法：全局数组 + 映射函数）
   定义：|i - j| <= 1 的元素才可能非零，其余全为 0。
        第 0 行 2 个元素，第 1 .. n-2 行各 3 个，第 n-1 行 2 个，
        总长度 = 2 + 3(n-2) + 2 = 3n - 2。
   （若题目改成「按对角线存进 3×n 的数组」，长度就是 3n，看清题面）

   按行优先压进 sa[0 .. 3n-3]：
       i = 0  : k = j                     （j = 0, 1）
       i >= 1 : k = 3i - 1 + (j - i + 1)  （前 i 行共 2 + 3(i-1) = 3i-1 个元素，
                                            本行内偏移是 j - (i-1)）
   两个式子可以统一写成：k = 2i + j   （在 |i - j| <= 1 的前提下）
   反向公式：i = floor((k+1)/3)，j = k - 2i
   ============================================================ */

const int N = 1005;            /* 最大阶数 */
int sa[3 * N];                 /* 压缩数组，长度 3n - 2（开 3N 个单元够用） */
int n;                         /* 矩阵阶数 */

/* 一维下标公式：k = 2i + j，只要求 |i-j| <= 1 */
inline int idx(int i, int j) { return 2 * i + j; }

/* 带内判断：|i - j| > 1 的位置压缩后根本没存，逻辑上恒为 0 */
inline bool inBand(int i, int j) { return abs(i - j) <= 1; }

/* 反向映射：已知一维下标 k，反求它在矩阵中的位置 (i, j) */
inline void decode(int k, int &i, int &j) { i = (k + 1) / 3; j = k - 2 * i; }

/* 边界检查：竞赛里不抛异常，越界就打印提示 */
bool inRange(int i, int j) {
    if (0 <= i && i < n && 0 <= j && j < n) return true;
    printf("  [warn] (%d, %d) out of range\n", i, j);
    return false;
}

/* 存：带外的位置不存储，只允许写 0（写别的值说明调用者的逻辑已经错了） */
bool setVal(int i, int j, int v) {
    if (!inRange(i, j)) return false;
    if (!inBand(i, j)) {
        if (v != 0) {
            printf("  [warn] a[%d][%d] 在带外，必须是 0\n", i, j);
            return false;
        }
        return true;                     /* 带外的 0 根本不存储 */
    }
    sa[idx(i, j)] = v;
    return true;
}

/* 取：带外一律是 0，这个判断同样是 O(1) */
int getVal(int i, int j) {
    if (!inRange(i, j)) return 0;
    return inBand(i, j) ? sa[idx(i, j)] : 0;
}

/* 打印整个一维数组，方便与手算结果对照 */
void dump() {
    int len = 3 * n - 2;
    for (int k = 0; k < len; ++k) printf("%d%c", sa[k], k + 1 == len ? '\n' : ' ');
}

int main() {
    n = 5;
    for (int i = 0; i < n; ++i)
        for (int j = 0; j < n; ++j)
            if (inBand(i, j)) setVal(i, j, i * 10 + j);   /* a[i][j] = i*10 + j */

    printf("n = 5, storage size = %d (3n - 2 = %d)\n", 3 * n - 2, 3 * n - 2);  /* 13 */
    printf("a[0][1] = %d, k = %d\n", getVal(0, 1), idx(0, 1));   /* 1, 1 */
    printf("a[2][2] = %d, k = %d\n", getVal(2, 2), idx(2, 2));   /* 22, 6 */
    printf("a[4][3] = %d, k = %d\n", getVal(4, 3), idx(4, 3));   /* 43, 11 */
    printf("a[3][0] = %d  (out of band -> 0, not stored)\n", getVal(3, 0));
    printf("sa[] = ");
    dump();                       /* 0 1 10 11 12 21 22 23 32 33 34 43 44 */

    printf("reverse mapping k -> (i, j):\n  ");
    for (int k = 0; k < 3 * n - 2; ++k) {
        int i, j;
        decode(k, i, j);
        printf("k%d=a[%d][%d]  ", k, i, j);
    }
    printf("\n");

    /* 带外写非 0 值会被拦住 */
    printf("setVal(3, 0, 99) -> %s\n", setVal(3, 0, 99) ? "true" : "false");
    return 0;
}

现在回答导读里埋的那个问题：带状矩阵压缩之后，为什么随机存取能力一点没丢？ 原因可以拆成三条：

  1. 映射是闭式的。k = 2i + j 只包含一次乘法和一次加法， 与 n 无关，也与「前面存了多少」无关——不需要扫描、不需要累加、不需要查表。 计算机执行它就是一条 lea 指令的事。
  2. 带外的元素不需要「找」，逻辑上直接是 0。压缩存储的前提就是 「没存的位置就是 0」，所以 getVal 只要先判断 |i−j| ≤ 1， 不满足就 return 0。这个判断也是 O(1)。
  3. 它和原来的二维数组一样是「连续 + 等长」的。压缩后仍然是一个普通的一维数组， sa[k] 本身还是 O(1)。压缩只是把「二维下标」翻译成「一维下标」， 并没有改变底层存储方式。

对比一下稀疏矩阵就清楚了：稀疏矩阵的非零元位置无法用不等式描述， 所以既写不出闭式 k = f(i,j)，也无法用「带外恒为 0」这种简单规则兜底， 只能老老实实把位置存下来再查找。这就是本书 6.7 节要处理的问题。

6.7 稀疏矩阵及其压缩存储

6.7.1 什么是稀疏矩阵：公式法为什么在这里失灵

稀疏矩阵（sparse matrix）是指非零元素个数远小于矩阵元素总数的矩阵。 国内教材通常给出一个量化标准：若非零元个数占元素总数的比例不超过 5% （即 tu / (mu × nu) ≤ 0.05），就认为它是稀疏的。

这个「5%」只是个工程上的经验界，不要当成数学定义去较真。真正要抓住的是两点：

  • 稀疏是「比例」概念，不是「规模」概念。一个 1000000 × 1000000 的矩阵， 如果每个位置都非零，它依然是稠密矩阵；反过来，一个 10 × 10 的矩阵只要有 2 个非零元， 按比例说它也是稀疏的（只是这时候压缩反而可能不划算）。
  • 稀疏矩阵的价值在于「省空间」和「省时间」。工程上（有限元、图计算、推荐系统） 动辄百万阶的稀疏矩阵，用稠密方式存根本开不出内存；而很多算法（比如稀疏矩阵向量乘） 可以做到只与非零元个数成正比，与矩阵阶数几乎无关。

现在回答关键问题：为什么对称矩阵、三角矩阵、三对角矩阵那套「公式法」在稀疏矩阵上不行？

回忆 6.3.3 的三步法。第一步要「确定存哪些元素」，也就是用下标不等式把非零区域描述出来。 对称矩阵能写成 i ≥ j，三对角能写成 |i − j| ≤ 1， 有了这样的不等式，第三步的「数前面有多少个元素」才能变成等差数列求和， 最终得到闭式的 k = f(i,j)。

而一般稀疏矩阵的零元素是东一个西一个、毫无规律的：它可能出现在 (0,3)，也可能出现在 (17,92)，两个非零元之间没有任何位置上的约束关系。 既然写不出不等式，也就数不出「前面有多少个」，公式法直接失灵。

于是只剩一条路：把「位置」也存下来 既然位置算不出来，那就把位置和值一起存：每个非零元存成一个 (行号, 列号, 值) 的三元组。这样虽然每个元素多花了两个整数的开销， 但比起「用 mu × nu 个单元去存一大堆 0」，当稀疏度足够低时仍然是稳赚的。
代价是：按下标随机取值（随机存取）的能力基本上没有了——要找一个元素， 只能按某种顺序去查找。

6.7.2 三元组顺序表：最朴素也最常用的方案

三元组顺序表（sequential list of triples）是稀疏矩阵最经典的顺序存储结构。 它的定义短得可以背下来：用一个结构体数组，按行优先顺序 （行号升序；同一行内列号升序）存放全部非零元，每个元素包含 row、col、value 三个域； 另外用 mu、nu、tu 记录行数、列数和非零元个数。

为什么要规定「按行优先有序」？因为有序带来三个直接好处： 可以按行处理（矩阵加法、乘法都要按行归并）、转置时能一次定位、 打印和调试时输出可读。代价是插入或修改一个元素时可能要搬移后续元素—— 和顺序表一样的老毛病。

结构定义与「朴素转置」的实现在下面。请特别留意朴素转置的复杂度是怎么来的—— 它其实就是「按列扫描 + 全表查找」这个笨办法的代价： 

#include <bits/stdc++.h>
using namespace std;

/* ============================================================
   稀疏矩阵的三元组顺序表 + 朴素转置（竞赛写法：全局数组 + 自由函数）
   三元组：(row, col, value)，按"行优先"排列（行号升序，同行按列号升序）。
   struct Triple 只描述"一个非零元长什么样"，属于结点型，保留；
   矩阵本体就是一个三元组数组 + 三个计数器（mu / nu / tu），不必再套一层 struct。

   朴素转置的思路：
       转置后 T 的第 col 行 = M 的第 col 列。
       于是依次枚举 M 的每一列 col = 0, 1, ..., nu-1，
       为了找到该列的所有非零元，每次都要把整个三元组表扫一遍。
       扫描次数 = nu * tu，所以时间复杂度 O(nu * tu)。
   ============================================================ */

struct Triple {                 /* 结点型：一个非零元 = 行号 + 列号 + 值 */
    int r, c, v;
};

const int MAXT = 100;           /* 数组开够：本题非零元个数 ≤ 100（竞赛里按题目上限开） */

Triple t[MAXT];                 /* 转置结果 T 的三元组表 */
int mu, nu, tu;                 /* T 的行数、列数、非零元个数 */

/* 往 T 里追加一个非零元 —— 三元组表的"插入"就是这一步 */
void pushTriple(int r, int c, int v) {
    t[tu].r = r; t[tu].c = c; t[tu].v = v;
    ++tu;
}

void printMatrix(const char* name) {
    cout << name << " : " << mu << " x " << nu << ", tu = " << tu << "\n";
    for (int p = 0; p < tu; ++p)
        cout << "   [" << p << "] (" << t[p].r << ", " << t[p].c
             << ", " << t[p].v << ")\n";
}

/* 朴素转置：把 src（stu 个非零元、smu 行 snu 列）转置后存进全局的 t[]，O(snu * stu) */
void naiveTranspose(const Triple src[], int stu, int smu, int snu) {
    mu = snu; nu = smu;                 /* 行列互换 */
    tu = stu;
    if (stu == 0) return;
    int q = 0;
    for (int col = 0; col < snu; ++col)               /* 枚举原矩阵的每一列 */
        for (int p = 0; p < stu; ++p)                 /* 每列都重扫整个三元组表 */
            if (src[p].c == col) {
                t[q].r = src[p].c;                    /* 行列互换 */
                t[q].c = src[p].r;
                t[q].v = src[p].v;
                ++q;
            }
}

int main() {
    /* 4 行 5 列，6 个非零元；总元素 20 个，稀疏度 30%（教学用小例子，真实场景常 < 5%） */
    Triple M[MAXT];
    int Mtu = 0;
    M[Mtu++] = {0, 1, 3};
    M[Mtu++] = {0, 4, 7};
    M[Mtu++] = {1, 2, 5};
    M[Mtu++] = {2, 0, 4};
    M[Mtu++] = {2, 3, 6};
    M[Mtu++] = {3, 1, 2};

    /* 为了能同框打印两个矩阵，把 M 的内容也放进全局表里，用 printMatrix 输出 */
    mu = 4; nu = 5; tu = 0;
    for (int p = 0; p < Mtu; ++p) pushTriple(M[p].r, M[p].c, M[p].v);
    printMatrix("M");

    naiveTranspose(M, Mtu, 4, 5);
    printMatrix("T = M^T (naive transpose)");
    return 0;
}

6.7.3 转置：朴素算法为什么慢

矩阵转置（transpose）在数学上很简单：T[j][i] = M[i][j]。 对三元组表来说，把每个三元组的 row 和 col 交换一下就行。 但请注意：光交换还不够。交换之后，数组里的顺序变成了「按原来的列优先」， 不再是「按行优先有序」了，而我们的结构约定要求它必须有序，所以还得重新排。

朴素算法的想法是：不去排序，而是按目标顺序直接产生。 转置后 T 的第 col 行来自 M 的第 col 列， 于是我按 col = 0, 1, …, nu−1 的顺序，依次把 M 中所有列号为 col 的三元组找出来、交换行列、追加到 T 里。 因为「先处理列号小的」，产出的 T 自然就是按行有序的。

问题在于「找出来」这一步：为了找第 col 列的所有非零元， 我们必须把整个三元组表从头到尾扫一遍。一共有 nu 列， 每列都扫 tu 个元素，于是：

时间复杂度 = O(nu × tu)　空间复杂度 = O(tu)（存放结果）

这个复杂度有多糟？考虑一个 n × n 的稀疏矩阵，若 tu 与 n 同阶 （比如每行平均只有常数个非零元），那 O(nu × tu) = O(n²)—— 和直接把稠密二维数组转置一遍一样慢，等于白折腾。显然需要改进。

6.7.4 快速转置：num[] 与 cpot[] 的递推

快速转置（fast transpose）的核心洞察只有一句话： 如果能事先知道「转置后第 col 行的第一个元素应该放在哪个位置」， 那么只需要扫一遍 M.data，边扫边放，转置就完成了。

为此需要两个辅助数组，长度都是 nu（转置后的行数）：

num[col]
M 中第 col 列的非零元个数。 因为 M 的列就是 T 的行，所以它同时也是 T 中第 col 行的元素个数。
cpot[col]
T 中第 col 行的第一个元素应该放在 T.data 的哪个下标处（cpot = column position）。

num 很好求：扫一遍 M.data，对每个三元组 ++num[它的 col] 即可。 cpot 则用前缀和递推出来：

cpot[0] = 0
cpot[col] = cpot[col−1] + num[col−1]　（col = 1, 2, …, nu−1）

这两行的意思很直白：第 col 行的起点 = 第 col−1 行的起点 + 第 col−1 行有多少个元素。 就像排队时分座位：前面那队有多少人，我这队就从下一个空位开始坐。

用图 6-8 里的矩阵 M 实际推一遍（mu=4, nu=5, tu=6）：

  • cpot[0] = 0（人为约定：第一行从 0 号位开始）。
  • cpot[1] = cpot[0] + num[0] = 0 + 1 = 1。
  • cpot[2] = cpot[1] + num[1] = 1 + 2 = 3。
  • cpot[3] = cpot[2] + num[2] = 3 + 1 = 4。
  • cpot[4] = cpot[3] + num[3] = 4 + 1 = 5。
  • 校验：cpot[4] + num[4] = 5 + 1 = 6 = tu ✅ 刚好把 6 个位置分配完， 这也是一条常用的自检规则。

快速转置的完整实现如下，三个步骤在注释里标了序号：

#include <bits/stdc++.h>
using namespace std;

/* ============================================================
   稀疏矩阵的快速转置 O(nu + tu)（竞赛写法：全局数组 + 自由函数）
   核心：先算出"转置后每一行从哪里开始放"，就能一次扫描直接定位。

   num[col]  = 原矩阵第 col 列的非零元个数（也就是 T 中第 col 行的元素个数）
   cpot[col] = T 中第 col 行第一个元素在 t[] 中的下标（cpot = column position）
       递推：cpot[0] = 0
             cpot[col] = cpot[col-1] + num[col-1]     (col = 1 .. nu-1)

   然后按原三元组表的顺序扫一遍：
       对每个三元组 (r, c, v)，它应该放在 t[cpot[c]]，
       放完后 ++cpot[c]，因为这一行的下一个元素要往后挪一格。
   ============================================================ */

struct Triple { int r, c, v; };   /* 结点型：一个非零元 */

const int MAXT = 100;             /* 数组开够：本题非零元个数 ≤ 100 */
const int MAXC = 100;             /* 列数上限：num / cpot 的长度依据 */

Triple t[MAXT];                   /* 转置结果 T 的三元组表 */
int mu, nu, tu;                   /* T 的行数、列数、非零元个数 */
int num[MAXC], cpot[MAXC];        /* ① 每列非零元个数  ② 每行起始下标 */

void pushTriple(int r, int c, int v) {   /* 三元组表的插入操作 */
    t[tu].r = r; t[tu].c = c; t[tu].v = v;
    ++tu;
}

void printMatrix(const char* name) {
    cout << name << " : " << mu << " x " << nu << ", tu = " << tu << "\n";
    for (int p = 0; p < tu; ++p)
        cout << "   [" << p << "] (" << t[p].r << ", " << t[p].c << ", " << t[p].v << ")\n";
}

/* 就地求 num[] / cpot[]：把 src 的列统计出来，供按行定位使用 */
void buildNumCpot(const Triple src[], int stu, int snu) {
    for (int col = 0; col < snu; ++col) num[col] = 0;
    for (int p = 0; p < stu; ++p) ++num[src[p].c];          /* ① 统计每列的非零元个数 */

    if (snu > 0) cpot[0] = 0;
    for (int col = 1; col < snu; ++col)                     /* ② 递推每行的起始位置 */
        cpot[col] = cpot[col - 1] + num[col - 1];
}

void fastTranspose(const Triple src[], int stu, int smu, int snu, bool verbose = false) {
    mu = snu; nu = smu;                                     /* 行列互换 */
    tu = stu;
    if (stu == 0) return;

    buildNumCpot(src, stu, snu);
    if (verbose) {
        cout << "col :"; for (int c = 0; c < snu; ++c) cout << "  " << c; cout << "\n";
        cout << "num :"; for (int c = 0; c < snu; ++c) cout << "  " << num[c]; cout << "\n";
        cout << "cpot:"; for (int c = 0; c < snu; ++c) cout << "  " << cpot[c]; cout << "\n";
    }

    for (int p = 0; p < stu; ++p) {                         /* ③ 一次扫描，直接定位 */
        int col = src[p].c;
        int q = cpot[col];
        t[q].r = src[p].c;
        t[q].c = src[p].r;
        t[q].v = src[p].v;
        ++cpot[col];                                        /* 该行的下一个空位 */
    }
}

int main() {
    Triple M[MAXT];
    int Mtu = 0;
    M[Mtu++] = {0, 1, 3};
    M[Mtu++] = {0, 4, 7};
    M[Mtu++] = {1, 2, 5};
    M[Mtu++] = {2, 0, 4};
    M[Mtu++] = {2, 3, 6};
    M[Mtu++] = {3, 1, 2};

    mu = 4; nu = 5; tu = 0;
    for (int p = 0; p < Mtu; ++p) pushTriple(M[p].r, M[p].c, M[p].v);
    printMatrix("M");

    fastTranspose(M, Mtu, 4, 5, true);
    printMatrix("T = M^T (fast transpose)");

    /* 快速转置的结果与"按行扫描"的期望完全一致：
       T 的第 0 行来自 M 的第 0 列 ... 依次类推 */
    return 0;
}
易错：最后一遍扫描的顺序不能乱 第三步必须按 M.data 原有的顺序（也就是行优先序）从头扫到尾。 为什么呢？因为 M.data 是按行号升序排列的， 所以当同一列（即 T 的同一行）的多个非零元被依次读到时， 它们的行号也一定是递增的，落进 T 的同一行后自然保持列号递增， 转置结果就仍然是有序的。
如果你自作聪明地按别的顺序扫描，转置结果的「行内有序」性质就没了， 后续的加法、乘法都会出错。
考点：两种转置的复杂度对比
算法时间辅助空间关键动作
朴素转置O(nu × tu)O(1)双重循环：外层枚举列，内层扫全表
快速转置O(nu + tu)O(nu)用 num/cpot 换时间（典型的空间换时间）
注意快速转置的空间是 O(nu)，不是 O(1)—— 考试问「辅助空间」时要答 O(nu)（有些书写 O(n)，n 指列数）。

6.7.5 行逻辑链接的顺序表：给三元组表加一个 rpos[]

三元组表虽然按行有序，但「第 i 行从哪儿开始」这件事它没说。 想知道第 3 行有哪些元素，你还是得从头扫或者二分查找，最坏 O(tu)。 解决办法和快速转置里用的一模一样——再加一个前缀和数组：

rpos[i] = 第 i 行第一个非零元在 data[] 中的下标，且约定 rpos[mu] = tu

建立了 rpos 之后，第 i 行的所有非零元就是 data[rpos[i] .. rpos[i+1]−1]，访问代价降为 O(该行非零元个数)。这种带行起始位置的三元组表，教材里叫 行逻辑链接的顺序表（row-logical linked list）—— 名字里的「链接」指的就是这个 rpos 起到的「逻辑链接」作用， 它并不是真的指针。

有了它，稀疏矩阵加法就能像归并两个有序数组那样按行做了： 对每一行 i，用两个指针分别扫 A 和 B 在该行的元素， 列号小的先输出、列号相等就相加。复杂度 O(tuA + tuB)。 

#include <bits/stdc++.h>
using namespace std;

/* ============================================================
   行逻辑链接的顺序表（Row-Logical Linked List）
   在三元组顺序表上增加一个 rpos[] 数组：
       rpos[i] = 第 i 行第一个非零元在 t[] 中的下标，rpos[mu] = tu
   递推：先数出每行的非零元个数，再做前缀和。
   有了 rpos[]，遍历第 i 行只需 O(该行非零元个数)，不用再扫全表。
   有了它，稀疏矩阵加法就能按行归并：O(tuA + tuB)。

   竞赛写法：A、B、C 三个矩阵各用"一组全局数组 + 三个计数器"表示，
   不再有 SparseMatrix 这层 struct 壳；struct Triple 描述非零元，保留。
   ============================================================ */

struct Triple { int r, c, v; };   /* 结点型：一个非零元 = 行号 + 列号 + 值 */

const int MAXT = 100;             /* 数组开够：每个矩阵非零元个数 ≤ 100 */
const int MAXR = 100;             /* 行数上限：rpos 的长度依据 */

/* ---------- A ---------- */
Triple ta[MAXT];
int muA, nuA, tuA;
int rposA[MAXR];
/* ---------- B ---------- */
Triple tb[MAXT];
int muB, nuB, tuB;
int rposB[MAXR];
/* ---------- C = A + B ---------- */
Triple tc[MAXT];
int muC, nuC, tuC;
int rposC[MAXR];

void pushA(int r, int c, int v) { ta[tuA].r = r; ta[tuA].c = c; ta[tuA].v = v; ++tuA; }
void pushB(int r, int c, int v) { tb[tuB].r = r; tb[tuB].c = c; tb[tuB].v = v; ++tuB; }
void pushC(int r, int c, int v) { tc[tuC].r = r; tc[tuC].c = c; tc[tuC].v = v; ++tuC; }

/* 建 rpos[]：两遍扫描，O(mu + tu) */
void buildRposA() {
    for (int i = 0; i <= muA; ++i) rposA[i] = 0;
    for (int p = 0; p < tuA; ++p) ++rposA[ta[p].r + 1];       /* ① 数每行的个数 */
    for (int i = 1; i <= muA; ++i) rposA[i] += rposA[i - 1];  /* ② 前缀和 */
}
void buildRposB() {
    for (int i = 0; i <= muB; ++i) rposB[i] = 0;
    for (int p = 0; p < tuB; ++p) ++rposB[tb[p].r + 1];
    for (int i = 1; i <= muB; ++i) rposB[i] += rposB[i - 1];
}
void buildRposC() {
    for (int i = 0; i <= muC; ++i) rposC[i] = 0;
    for (int p = 0; p < tuC; ++p) ++rposC[tc[p].r + 1];
    for (int i = 1; i <= muC; ++i) rposC[i] += rposC[i - 1];
}

void printA(const char* name) {
    cout << name << " : " << muA << " x " << nuA << ", tu = " << tuA << "\n";
    for (int p = 0; p < tuA; ++p)
        cout << "   [" << p << "] (" << ta[p].r << ", " << ta[p].c << ", " << ta[p].v << ")\n";
    cout << "   rpos =";
    for (int i = 0; i <= muA; ++i) cout << " " << rposA[i];
    cout << "\n";
}
void printB(const char* name) {
    cout << name << " : " << muB << " x " << nuB << ", tu = " << tuB << "\n";
    for (int p = 0; p < tuB; ++p)
        cout << "   [" << p << "] (" << tb[p].r << ", " << tb[p].c << ", " << tb[p].v << ")\n";
    cout << "   rpos =";
    for (int i = 0; i <= muB; ++i) cout << " " << rposB[i];
    cout << "\n";
}
void printC(const char* name) {
    cout << name << " : " << muC << " x " << nuC << ", tu = " << tuC << "\n";
    for (int p = 0; p < tuC; ++p)
        cout << "   [" << p << "] (" << tc[p].r << ", " << tc[p].c << ", " << tc[p].v << ")\n";
    cout << "   rpos =";
    for (int i = 0; i <= muC; ++i) cout << " " << rposC[i];
    cout << "\n";
}

/* 按行访问 A：打印第 i 行的所有非零元，复杂度 O(该行非零元个数) */
void printRowA(int i) {
    cout << "row " << i << " :";
    for (int p = rposA[i]; p < rposA[i + 1]; ++p)
        cout << "  col" << ta[p].c << "=" << ta[p].v;
    cout << "\n";
}

/* 稀疏矩阵加法 C = A + B（同型），按行归并，O(tuA + tuB) */
void addMatrix() {
    if (muA != muB || nuA != nuB) { printf("shape mismatch\n"); return; }
    muC = muA; nuC = nuA; tuC = 0;
    for (int i = 0; i < muA; ++i) {
        int pa = rposA[i], ea = rposA[i + 1];     /* A 的第 i 行区间 */
        int pb = rposB[i], eb = rposB[i + 1];     /* B 的第 i 行区间 */
        while (pa < ea && pb < eb) {
            int ca = ta[pa].c, cb = tb[pb].c;
            if (ca < cb) { pushC(i, ca, ta[pa].v); ++pa; }
            else if (ca > cb) { pushC(i, cb, tb[pb].v); ++pb; }
            else {
                int s = ta[pa].v + tb[pb].v;
                if (s != 0) pushC(i, ca, s);   /* 相加为 0 就不必存了 —— 稀疏矩阵加法的关键细节 */
                ++pa; ++pb;
            }
        }
        for (; pa < ea; ++pa) pushC(i, ta[pa].c, ta[pa].v);
        for (; pb < eb; ++pb) pushC(i, tb[pb].c, tb[pb].v);
    }
}

int main() {
    muA = 4; nuA = 5; tuA = 0;
    pushA(0, 1, 3); pushA(0, 4, 7); pushA(1, 2, 5);
    pushA(2, 0, 4); pushA(2, 3, 6); pushA(3, 1, 2);

    muB = 4; nuB = 5; tuB = 0;
    pushB(0, 4, -7); pushB(1, 2, 5); pushB(2, 0, -4);
    pushB(2, 3, 6);  pushB(3, 2, 9);

    buildRposA(); buildRposB();
    printA("A"); printB("B");

    printRowA(0);
    printRowA(2);

    addMatrix();
    buildRposC();
    printC("C = A + B");

    /* 注意看：C 的第 0 行只剩 (0,1,3)，
       因为 A(0,4,7) + B(0,4,-7) = 0，这个位置直接"消失"了。 */
    return 0;
}

运行结果里最值得看的一处是：C 的第 0 行只剩下 (0,1,3) 一项， 因为 A(0,4,7) + B(0,4,−7) = 0，这个位置在结果里直接消失了。 代码里那一句 if (s != 0) C.push(...) 就是稀疏矩阵运算的典型风格： 结果为零的位置绝不存储。

6.7.6 十字链表：能按行也能按列，还便于增删

三元组表有两个绕不开的弱点：一是插入删除要搬移元素，二是按列访问很不方便。 而矩阵运算（尤其是乘法、加法这类会「边算边生成新非零元」的场景）恰恰需要频繁插入， 也常常需要按列扫描。于是有了链式方案——十字链表（orthogonal list）。

它把矩阵的每个非零元做成一个结点，结点有五个域： row（行号）、col（列号）、value（值）、 down（指向同列下一个非零元）、right（指向同行下一个非零元）。 再加上两个表头指针数组：

  • rhead[mu]：rhead[i] 指向第 i 行的第一个非零元， 顺着 right 就能走完整行；
  • chead[nu]：chead[j] 指向第 j 列的第一个非零元， 顺着 down 就能走完整列。

两条链表在同一个结点上「十字交叉」，所以叫十字链表。 它的最大好处是：插入或删除一个非零元时，只需要改动常数个指针，不用搬移任何数据 （这也是所有链式结构的共同优点），而且「按行」和「按列」两条访问路径都是现成的。

实现十字链表的关键技巧是「用指针的指针找插入点」： 要往一条有序链表里插入，不必区分「插在头部」和「插在中间」两种情况， 只要用一个二级指针 OLNode** p 一路往后走，最后 *p = node 就完事了。 下面的代码同时演示了「按行列有序插入」和「同一位置重复插入时累加」两个细节： 

#include <bits/stdc++.h>
using namespace std;

/* ============================================================
   十字链表（Orthogonal List）—— 稀疏矩阵的链式存储（竞赛写法）
   每个非零元是一个含 5 个域的结点：
       row, col, value, down, right
   right 把同一行的非零元串成链表（按列号升序）；
   down  把同一列的非零元串成链表（按行号升序）。
   另外用两个指针数组作为表头：rhead[mu]（行）、chead[nu]（列）。

   优点：插入 / 删除非零元不用像顺序表那样成片搬移元素，
         而且「按行」和「按列」两条访问路径都是 O(1) 起步。
   代价：每个结点多两个指针域；按下标 (i,j) 随机取值退化成沿链查找。
   ============================================================ */

const int N = 1005;                 /* 行数、列数上限 */
struct OLNode {                     /* 结点：5 个域 */
    int r, c, v;                    /* 行号、列号、值 */
    OLNode *down, *right;           /* down = 同列下一个，right = 同行下一个 */
};

OLNode *rhead[N], *chead[N];        /* 行 / 列表头指针数组 */
int mu, nu, tu;                     /* 行数、列数、非零元个数 */

/* 初始化成 mu 行 nu 列的空矩阵：表头全部置空 */
void initMatrix(int m, int n) {
    mu = m; nu = n; tu = 0;
    for (int i = 0; i < mu; ++i) rhead[i] = nullptr;
    for (int j = 0; j < nu; ++j) chead[j] = nullptr;
}

/* 新建结点；竞赛里干脆不写 delete，程序结束内存就还给操作系统了 */
OLNode* newNode(int r, int c, int v) {
    OLNode* p = new OLNode;
    p->r = r; p->c = c; p->v = v;
    p->down = p->right = nullptr;
    return p;
}

/* 插入（或累加）一个非零元，保持行、列两条链表都有序 */
void insertNode(int r, int c, int v) {
    if (v == 0) return;                        /* 0 不是非零元，不入表 */

    /* ① 先在第 r 行的行链表里找插入点（按列号升序）
          「用指针的指针找插入点」：不必区分插在头部还是中间，
          一路往后走，最后 *rp = node 一句就搞定 */
    OLNode** rp = &rhead[r];
    while (*rp && (*rp)->c < c) rp = &(*rp)->right;
    if (*rp && (*rp)->c == c) {                /* 该位置已经有结点了 → 只累加值 */
        (*rp)->v += v;                         /* 列链表里挂的是同一个结点，不用再动 */
        return;
    }
    OLNode* node = newNode(r, c, v);
    node->right = *rp;                         /* 先接后面，再改前面，顺序不能反 */
    *rp = node;

    /* ② 再挂到第 c 列的列链表（按行号升序） */
    OLNode** cp = &chead[c];
    while (*cp && (*cp)->r < r) cp = &(*cp)->down;
    node->down = *cp;
    *cp = node;

    ++tu;
}

void printByRow() {
    printf("by row:\n");
    for (int i = 0; i < mu; ++i) {
        printf("  row %d :", i);
        for (OLNode* p = rhead[i]; p; p = p->right)
            printf("  (%d,%d,%d)", p->r, p->c, p->v);
        printf("\n");
    }
}
void printByCol() {
    printf("by col:\n");
    for (int j = 0; j < nu; ++j) {
        printf("  col %d :", j);
        for (OLNode* p = chead[j]; p; p = p->down)
            printf("  (%d,%d,%d)", p->r, p->c, p->v);
        printf("\n");
    }
}
int nonzeros() { return tu; }

int main() {
    initMatrix(4, 5);
    insertNode(0, 1, 3);
    insertNode(0, 4, 7);
    insertNode(1, 2, 5);
    insertNode(2, 0, 4);
    insertNode(2, 3, 6);
    insertNode(3, 1, 2);
    insertNode(0, 1, 10);          /* 同一位置的再次插入 → 值累加为 13 */
    insertNode(1, 1, 1);           /* 插在已存在的列链表中间，链式结构无需搬移 */

    printf("nonzeros = %d\n", nonzeros());
    printByRow();
    printByCol();
    return 0;
}
考点：十字链表的结点结构 这是最经典的画图题之一，务必能默画出来：五个域 （row、col、value、down、right） 加上两个表头数组（rhead[]、chead[]）。 常见的追问有二：
  • 「十字链表能不能随机存取？」不能。要访问 a[i][j]， 得从 rhead[i] 出发沿 right 逐个比较列号， 代价 O(该行非零元个数)。
  • 「它比三元组表好在哪？」插入删除只改指针、不用搬移； 行、列两个方向都能高效遍历；非零元个数动态变化时不用预估容量。

6.7.7 工程视角：CSR / CSC 格式

前面讲的三种结构都是教材语言。真到了工程里（SciPy、PETSc、cuSPARSE、PyTorch 的稀疏张量）， 用得最多的是 CSR（Compressed Sparse Row，压缩稀疏行）格式。 它其实是「三元组表 + rpos」的极致版本——把行号也省掉了（三个数组与原矩阵的对应关系见图 6-11）：

数组长度含义
values[]nnz按行优先顺序存放的全部非零元的值
colIdx[]nnz与 values[] 一一对应的列号
rowPtr[]m + 1 第 i 行的非零元区间是 [rowPtr[i], rowPtr[i+1])； 约定 rowPtr[0] = 0、rowPtr[m] = nnz

注意 rowPtr 和行逻辑链接里的 rpos 是同一个东西， 只是多存了一个哨兵 rowPtr[m] = nnz，这样每行的区间都能写成半开区间 [rowPtr[i], rowPtr[i+1])，代码里少一个 if。

为什么说 CSR 是 cache 友好的？看稀疏矩阵向量乘 y = Ax 的循环：

for (int i = 0; i < m; ++i)
    for (int p = rowPtr[i]; p < rowPtr[i + 1]; ++p)  // 连续的一段！
        y[i] += values[p] * x[colIdx[p]];

内层循环在 values[] 和 colIdx[] 上是严格顺序前进的， 这正是 CPU 预取器和缓存最喜欢的访问模式：读入 values[p] 时， 同一缓存行里的后面十几个元素也一起进了缓存，接下来的迭代几乎是零开销。 相比之下，十字链表每访问一个元素都要解引用一个指针，地址完全随机， 每次都可能是一次缓存未命中（cache miss）；而三元组表虽然也顺序， 但每个元素多存了一个行号，且没有「按行定位」的能力。

代价是 CSR 的「结构是静态的」：rowPtr 靠前缀和一次性算好， 中途插入一个非零元会导致后面所有位置整体后移。所以 CSR 适合「结构定下来之后反复做运算」 （迭代求解、稀疏矩阵乘法、图算法），不适合「边算边改结构」。 列优先的版本叫 CSC（Compressed Sparse Column），把行、列的角色对调， 适用于按列访问更频繁的场合（比如 MATLAB 历史上就用 CSC）。 

#include <iostream>
#include <vector>
#include <iomanip>
using namespace std;

/* ============================================================
   CSR（Compressed Sparse Row，压缩稀疏行）
   现代工程里最常用的稀疏矩阵格式，由三个一维数组构成：

       values[] : 按行优先顺序排列的全部非零元的值
       colIdx[] : 与 values[] 一一对应的列号
       rowPtr[] : 长度为 m+1；第 i 行的非零元在 values[] 中的区间是
                  [rowPtr[i], rowPtr[i+1])

   为什么 cache 友好：
       第 i 行的数据在 values[]/colIdx[] 里是"连续的一整段"，
       遍历一行时访存完全顺序，不像十字链表那样满内存跳指针；
       而且除了这三个数组外没有任何指针开销。
   ============================================================ */

struct Triple { int r, c, v; };

struct CSR {
    int m, n;
    vector<int> values, colIdx, rowPtr;
};

CSR buildCSR(int m, int n, const vector<Triple>& trips) {
    CSR A; A.m = m; A.n = n;
    A.rowPtr.assign(m + 1, 0);
    for (size_t p = 0; p < trips.size(); ++p) ++A.rowPtr[trips[p].r + 1];   /* ① 数每行个数 */
    for (int i = 1; i <= m; ++i) A.rowPtr[i] += A.rowPtr[i - 1];           /* ② 前缀和 */

    A.values.assign(trips.size(), 0);
    A.colIdx.assign(trips.size(), 0);
    vector<int> pos(A.rowPtr.begin(), A.rowPtr.end() - 1);                 /* ③ 每行的写入位置 */
    for (size_t p = 0; p < trips.size(); ++p) {
        int q = pos[trips[p].r]++;
        A.values[q] = trips[p].v;
        A.colIdx[q] = trips[p].c;
    }
    return A;
}

void printCSR(const CSR& A, const char* name) {
    cout << name << " (" << A.m << " x " << A.n << ", nnz = "
         << A.values.size() << ")\n";
    cout << "  rowPtr ="; for (size_t i = 0; i < A.rowPtr.size(); ++i) cout << " " << A.rowPtr[i]; cout << "\n";
    cout << "  colIdx ="; for (size_t i = 0; i < A.colIdx.size(); ++i) cout << " " << A.colIdx[i]; cout << "\n";
    cout << "  values ="; for (size_t i = 0; i < A.values.size(); ++i) cout << " " << A.values[i]; cout << "\n";
}

/* 稀疏矩阵 × 稠密向量 y = A x，复杂度 O(nnz)，是迭代法解线性方程组的核心算子 */
vector<double> spmv(const CSR& A, const vector<double>& x) {
    vector<double> y(A.m, 0.0);
    for (int i = 0; i < A.m; ++i)
        for (int p = A.rowPtr[i]; p < A.rowPtr[i + 1]; ++p)
            y[i] += A.values[p] * x[A.colIdx[p]];
    return y;
}

int main() {
    vector<Triple> trips = {
        {0, 1, 3}, {0, 4, 7}, {1, 2, 5},
        {2, 0, 4}, {2, 3, 6}, {3, 1, 2}
    };
    CSR A = buildCSR(4, 5, trips);
    printCSR(A, "A");

    vector<double> x = {1, 2, 3, 4, 5};
    vector<double> y = spmv(A, x);
    cout << "y = A x =";
    for (size_t i = 0; i < y.size(); ++i) cout << " " << y[i];
    cout << "\n";     /* 41 15 28 4 —— 手算：3*2+7*5=41，5*3=15，4*1+6*4=28，2*2=4 */
    return 0;
}

6.7.8 稀疏矩阵的加法与乘法

加法在 6.7.5 已经见过：按行归并，O(tuA + tuB)， 关键是「结果为零的位置不存」。这里再强调一个实战中的坑： 稀疏 + 稀疏未必还是稀疏。如果两个矩阵的非零位置几乎不重叠， 结果的非零元个数可能是两者之和（这叫 fill-in，填充）， 极端情况下结果会变成稠密矩阵。所以工程库在处理前通常会先估算结果的 nnz 上界。

乘法稍微绕一点。设 C = A × B，A 是 m × n， B 是 n × p。如果直接照抄三重循环的稠密写法， 复杂度是 O(m × n × p)，完全没利用稀疏性。 正确姿势是「以 A 的非零元为驱动」：

  1. 开一个长度为 p 的累加器数组 ctemp[]，初值全 0；
  2. 对 A 的第 i 行，遍历它的每个非零元 a[i][k]；
  3. 把 a[i][k] 乘到 B 第 k 行的每个非零元 b[k][j] 上， 累加进 ctemp[j]；
  4. 第 i 行处理完，把 ctemp 中的非零项收进 C 的第 i 行，然后把 ctemp 清零。

复杂度是 O(m × p + Σa[i][k]≠0 (B 第 k 行的非零元个数))—— 只有当 B 的行很稠密时才会退化。这一段代码里 rpos[] 再次出场， 用来 O(1) 定位 B 的每一行： 

#include <bits/stdc++.h>
using namespace std;

/* ============================================================
   稀疏矩阵乘法 C = A x B（行逻辑链接版，竞赛写法：全局数组 + 自由函数）
   设 A 是 m x n，B 是 n x p。
   思路：对 A 的第 i 行的每个非零元 a[i][k]，
         把它乘到 B 的第 k 行的每个非零元 b[k][j] 上，
         结果累加到临时行 ctemp[j] 里；第 i 行处理完，
         把 ctemp 中的非零项收集成 C 的第 i 行。
   复杂度：O(m*p + sum_{a[i][k] != 0} (B 第 k 行的非零元个数))

   这里 A、B、C 各用"三元组全局数组 + rpos[] + 三个计数器"表示；
   struct Triple 只描述非零元，属于结点型，保留。
   ============================================================ */

struct Triple { int r, c, v; };   /* 结点型：一个非零元 */

const int MAXT = 100;             /* 数组开够：每个矩阵非零元个数 ≤ 100 */
const int MAXR = 100;             /* 行数上限：rpos 的长度依据 */
const int MAXC = 100;             /* 列数上限：ctemp 的长度依据 */

/* ---------- A ---------- */
Triple ta[MAXT];
int muA, nuA, tuA, rposA[MAXR];
/* ---------- B ---------- */
Triple tb[MAXT];
int muB, nuB, tuB, rposB[MAXR];
/* ---------- C = A x B ---------- */
Triple tc[MAXT];
int muC, nuC, tuC, rposC[MAXR];

int ctemp[MAXC];                  /* 累加 C 当前这一行的结果 */

void pushA(int r, int c, int v) { ta[tuA].r = r; ta[tuA].c = c; ta[tuA].v = v; ++tuA; }
void pushB(int r, int c, int v) { tb[tuB].r = r; tb[tuB].c = c; tb[tuB].v = v; ++tuB; }
void pushC(int r, int c, int v) { tc[tuC].r = r; tc[tuC].c = c; tc[tuC].v = v; ++tuC; }

void buildRposA() {
    for (int i = 0; i <= muA; ++i) rposA[i] = 0;
    for (int p = 0; p < tuA; ++p) ++rposA[ta[p].r + 1];
    for (int i = 1; i <= muA; ++i) rposA[i] += rposA[i - 1];
}
void buildRposB() {
    for (int i = 0; i <= muB; ++i) rposB[i] = 0;
    for (int p = 0; p < tuB; ++p) ++rposB[tb[p].r + 1];
    for (int i = 1; i <= muB; ++i) rposB[i] += rposB[i - 1];
}
void buildRposC() {
    for (int i = 0; i <= muC; ++i) rposC[i] = 0;
    for (int p = 0; p < tuC; ++p) ++rposC[tc[p].r + 1];
    for (int i = 1; i <= muC; ++i) rposC[i] += rposC[i - 1];
}

void printA(const char* name) {
    cout << name << " : " << muA << " x " << nuA << ", tu = " << tuA << "\n";
    for (int p = 0; p < tuA; ++p)
        cout << "   (" << ta[p].r << ", " << ta[p].c << ", " << ta[p].v << ")\n";
}
void printB(const char* name) {
    cout << name << " : " << muB << " x " << nuB << ", tu = " << tuB << "\n";
    for (int p = 0; p < tuB; ++p)
        cout << "   (" << tb[p].r << ", " << tb[p].c << ", " << tb[p].v << ")\n";
}
void printC(const char* name) {
    cout << name << " : " << muC << " x " << nuC << ", tu = " << tuC << "\n";
    for (int p = 0; p < tuC; ++p)
        cout << "   (" << tc[p].r << ", " << tc[p].c << ", " << tc[p].v << ")\n";
}

void multiply() {
    if (nuA != muB) { printf("shape mismatch: A.nu != B.mu\n"); return; }
    muC = muA; nuC = nuB; tuC = 0;
    if (tuA == 0 || tuB == 0) return;

    for (int i = 0; i < muA; ++i) {
        for (int j = 0; j < nuB; ++j) ctemp[j] = 0;    /* 清空累加器 */
        for (int pa = rposA[i]; pa < rposA[i + 1]; ++pa) {
            int k = ta[pa].c;                         /* A 的列 = B 的行 */
            for (int pb = rposB[k]; pb < rposB[k + 1]; ++pb) {
                int j = tb[pb].c;
                ctemp[j] += ta[pa].v * tb[pb].v;
            }
        }
        for (int j = 0; j < nuB; ++j)
            if (ctemp[j] != 0) pushC(i, j, ctemp[j]);  /* 只保留非零元 */
    }
    buildRposC();
}

int main() {
    muA = 3; nuA = 4; tuA = 0;
    pushA(0, 0, 1); pushA(0, 2, 2); pushA(1, 1, 3);
    pushA(2, 0, 4); pushA(2, 3, 5);

    muB = 4; nuB = 2; tuB = 0;
    pushB(0, 0, 1); pushB(0, 1, 2); pushB(1, 1, 1);
    pushB(2, 0, 3); pushB(3, 0, 1); pushB(3, 1, 1);

    buildRposA(); buildRposB();
    printA("A"); printB("B");

    multiply();
    printC("C = A x B");
    /* 手算对照：
       C[0][0] = 1*1 + 2*3 = 7      C[0][1] = 1*2 + 2*0 = 2
       C[1][0] = 3*0 = 0（不存）    C[1][1] = 3*1 = 3
       C[2][0] = 4*1 + 5*1 = 9      C[2][1] = 4*2 + 5*1 = 13  */
    return 0;
}

四种稀疏结构的选型建议
  • 只读、要转置、要考试 → 三元组顺序表（写起来最简单，考试也只考它）。
  • 要按行反复访问 → 行逻辑链接的顺序表（加一个 rpos[]，改动最小、收益最大）。

6.9 本章小结、易错点与自测

6.9.1 必须记住的六件事

概念与公式

  1. 数组是线性表的推广：一维数组是线性表，二维数组是元素为线性表的线性表。
  2. 随机存取的根基是「等长 + 连续」，地址是下标的线性函数： LOC(a[k]) = LOC(a[0]) + k×L。
  3. 二维地址公式：行优先 (i×n + j)×L，列优先 (j×m + i)×L。 行优先乘列数、列优先乘行数。
  4. 压缩存储 = 「相同值只留一份 + 零元素不分配空间」，灵魂是下标映射函数 k = f(i,j)。
  5. 对称矩阵 k = i(i+1)/2 + j（i≥j），长度 n(n+1)/2。
  6. 三角矩阵长度 n(n+1)/2 + 1（常数占一格）； 上三角 k = i(2n−i+1)/2 + (j−i)。
  7. 三对角矩阵长度 3n − 2，k = 2i + j。
  8. 稀疏矩阵三元组：(row, col, value)；快速转置靠 num[] 与 cpot[]，O(nu+tu)。

四个「一句话本质」

  • 压缩存储：把「用下标算地址」变成「用一个函数算下标」，函数好算就赚，算不出来就退回存位置。
  • 等差求和：所有下标映射公式的最后一步都是「前 i 行共多少个」， 而这永远是 1+2+…+i = i(i+1)/2 或它的变体。
  • 快速转置：先用 num/cpot 把「每个元素该放哪」算好，再一趟扫描直接落位—— 典型的空间换时间。
  • 十字链表：一个结点同时挂在行链表和列链表上，于是「按行找」和「按列找」都变成了走链表。

6.9.2 易错点清单

致命错误（一犯就全错）
  • 行优先 / 列优先看反。题目说「按行优先存储」而你在用列优先公式， 后面每一步都错。做题第一件事：在草稿纸上写下用的是哪一套。
  • 忘记乘字节数 L。(i×n+j) 是「第几个元素」， 题目问「地址」时必须 × L。反过来，题目给的是地址、问的是位置时，要先 ÷ L。
  • 把 n(n+1)/2 写成 n(n−1)/2。这是漏掉主对角线的典型症状。 自检方法：代入 n = 1，长度应该是 1 而不是 0。
  • 三对角矩阵的 k = 2i + j 用在带外。这个统一公式只在 |i−j| ≤ 1 时成立；带外元素必须直接返回 0，否则会算出越界的下标。
  • 快速转置第三步不按原顺序扫描。会导致转置结果不再按行有序， 后续的加法乘法全部失效。
细节坑（容易被扣分）
  • 下标的起始值。本章统一用 0 基；若题目声明「下标从 1 开始」， 所有公式都要把 i, j 换成 i−1, j−1。
  • 三角矩阵多出来的那个单元。问「数组长度」要答 n(n+1)/2 + 1； 问「真实数据有多少个」才是 n(n+1)/2。
  • 上三角公式里的 (j − i)。漏掉它就等于假设每行都从第 0 列开始存了。
  • 带状矩阵的长度。3n − 2（按行压平）与 3n（按对角线存 3×n 数组） 是两个不同答案，看清题目的存储方案。
  • 稀疏矩阵相加时把 0 也存进去。结果位置相加为 0 时必须丢弃， 否则 tu 会虚高，稀疏结构逐渐退化。
  • 十字链表与三元组表的随机存取结论。两者都不保留 O(1) 随机存取， 别因为十字链表更高级就以为它能 O(1) 定位。

6.9.3 考点提示

历年高频考法
  1. 数组地址计算（几乎必考）。二维给首地址求某元素地址；或只给某一元素地址求另一元素 （用「增量法」）。三维数组也开始频繁出现，注意「哪一维变化最快，它的权重就是 1」。
  2. 对称矩阵的下标映射（最高频）。两种问法： ① 给 (i, j) 求 k； ② 给 k 反求 (i, j)（用 i(i+1)/2 ≤ k < (i+1)(i+2)/2 试根）。
  3. 三角矩阵的长度与常数位置。送分题，但要看清是上三角还是下三角、常数是几。
  4. 三对角矩阵的长度 3n−2 与公式 k = 2i + j。 常以填空形式出现，也常和「数组长度至少是多少」结合考。
  5. 稀疏矩阵的存储结构图。三元组表要能画出「有序」这个特点； 十字链表要能默画出五个域与两个表头数组，并说明 down / right 的作用。
  6. 快速转置的手算。给一个小矩阵，要求写出 num[]、cpot[] 以及转置结果的三元组表。这类题按「统计 → 前缀和 → 顺序落位」三步走，不容易错。
  7. 辨析题：压缩存储后是否还能随机存取？ 答「对称 / 三角 / 带状矩阵能（有闭式映射函数），稀疏矩阵不能（位置无规律）」。

6.9.4 自测题（先自己做，再展开看答案）

1. 【地址计算】二维数组 A[5][8]，每个元素 4 字节，LOC(a[0][0]) = 2000。求 a[3][6] 在行优先和列优先下的地址。

行优先：排在 a[3][6] 前面的是 3 整行加本行 6 个：

k = i×n + j = 3×8 + 6 = 30　⇒　LOC = 2000 + 30×4 = 2120

列优先：排在前面的是 6 整列加本列 3 个，每列有 m = 5 个元素：

k = j×m + i = 6×5 + 3 = 33　⇒　LOC = 2000 + 33×4 = 2132

两者相差 12 字节，也就是 3 个元素。可见「行优先 / 列优先」绝不是可以随便混用的小事。

2. 【地址计算·三维】三维数组 A[4][3][6]，每个元素 2 字节，LOC(a[0][0][0]) = 1000。求 a[2][1][4] 的地址（行优先）；再求 a[3][2][5] 的地址。

行优先，各维权重分别是「后面所有维度长度之积」：

i₁ 的权重 = 3×6 = 18；i₂ 的权重 = 6；i₃ 的权重 = 1
a[2][1][4]：k = 2×18 + 1×6 + 4 = 36 + 6 + 4 = 46　⇒　LOC = 1000 + 46×2 = 1092

求第二个时不必重算全部，用增量法更快：

a[3][2][5]：k = 3×18 + 2×6 + 5 = 54 + 12 + 5 = 71
Δk = 71 − 46 = 25　⇒　LOC = 1092 + 25×2 = 1142

提醒：A[4][3][6] 中 4 是第一维长度、3 是第二维、6 是第三维， 不要顺手把 4 当成最后一维。仔细看 A[d₁][d₂][d₃] 的写法。

3. 【下标映射】n = 7 的对称矩阵按「下三角 + 行优先」压缩。求 a[5][3] 与 a[3][5] 的位置，以及一维数组的长度和最大下标。

数组长度 n(n+1)/2 = 7×8/2 = 28，合法下标 0 ~ 27。

a[5][3]：i = 5 ≥ j = 3 ⇒ k = 5×6/2 + 3 = 15 + 3 = 18
a[3][5]：i = 3 < j = 5 ⇒ k = 5×6/2 + 3 = 15 + 3 = 18

两者当然相同：它们是同一个值的两个「镜像位置」，压缩后共用 sa[18]。

验证：第 5 行从 k = 5×6/2 = 15 开始， sa[15] = a[5][0]、sa[16] = a[5][1]、sa[17] = a[5][2]、 sa[18] = a[5][3] ✅

4. 【三对角矩阵】n = 8 的三对角矩阵按行优先压进 sa[]。求 a[6][5] 的位置、数组长度，以及 a[0][3] 的值。

数组长度 3n − 2 = 3×8 − 2 = 22，下标 0 ~ 21。

a[6][5]：|6 − 5| = 1 ≤ 1，在带内 ⇒ k = 2×6 + 5 = 17

a[0][3]：|0 − 3| = 3 > 1，在带外， 压缩后没有存储它，所以它的值恒为 0。

反向自检：k = 17 ⇒ i = ⌊18/3⌋ = 6，j = 17 − 12 = 5 ✅ 与题目吻合。

再验算一个边界：k = 21 ⇒ i = ⌊22/3⌋ = 7，j = 21 − 14 = 7， 即 a[7][7]，正好是最后一个元素 ✅

5. 【快速转置】稀疏矩阵 A（3 行 4 列）的三元组表为 (0,0,1) (0,3,2) (1,1,3) (2,0,4) (2,2,5)。 写出 num[]、cpot[]，并用快速转置算法求 T = Aᵀ 的三元组表。

第一步：统计 num[]（A 各列的非零元个数，共 nu = 4 列）：

第 0 列：(0,0)、(2,0) ⇒ 2　　第 1 列：(1,1) ⇒ 1　　第 2 列：(2,2) ⇒ 1　　第 3 列：(0,3) ⇒ 1
num = [2, 1, 1, 1]，合计 5 = tu ✅

第二步：前缀和求 cpot[]：

cpot[0] = 0
cpot[1] = cpot[0] + num[0] = 0 + 2 = 2
cpot[2] = cpot[1] + num[1] = 2 + 1 = 3
cpot[3] = cpot[2] + num[2] = 3 + 1 = 4
校验：cpot[3] + num[3] = 4 + 1 = 5 = tu ✅

第三步：按 A.data 原顺序扫描，逐个落位 （落一个就把对应的 cpot 加 1）：

读到col当前 cpot[col]写入 T 的位置写入内容
(0,0,1)00T[0](0,0,1)
(0,3,2)34T[4](3,0,2)
(1,1,3)12T[2](1,1,3)
(2,0,4)01T[1](0,2,4)
(2,2,5)23T[3](2,2,5)

按 T.data 下标排好，转置结果（4 行 3 列）为：

T = (0,0,1)　(0,2,4)　(1,1,3)　(2,2,5)　(3,0,2)

验证：A[2][0] = 4，转置后应该是 T[0][2] = 4， 结果里确实有 (0,2,4) ✅； A[0][3] = 2 ⇒ T[3][0] = 2，结果里有 (3,0,2) ✅。 并且 T 按行号严格升序 0,0,1,2,3，同行内列号升序 0 < 2 ✅ 有序性保持住了。

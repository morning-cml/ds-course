# 数据结构与算法设计 · 交互式课件

一套面向 C++ 学习者的**可交互、可离线**课件。所有抽象概念配结构图，所有核心算法配可单步 / 可自动播放的动态演示，
所有示例代码均为可直接编译运行的 C++。

| 规模 | 数量 |
|---|---|
| 讲次 | 15 讲 + 总览页 |
| 正文 | 约 32.1 万字（另含代码内注释约 5.7 万字） |
| 可单步交互动画 | 81 个（逐帧渲染共 2565 帧） |
| 静态结构图解 | 181 张内联 SVG（其中 11 张为可翻页的静态分步图） |
| C++ 代码 | 276 段，269 段通过 g++ 编译校验（7 段为需人工确认的片段） |

> 以上数字由 `node tools/stats.mjs` 实测得出，改课件后请重新跑一遍并同步本表。

## 快速开始

**双击 `index.html`** 即可开始学习。不需要安装任何东西，不需要联网。

- 建议用 Chrome / Edge / Firefox 打开（支持深色主题与打印导出 PDF）。
- 左侧是**课程章节目录**，点任意一讲即可跳过去，当前所在的一讲会高亮。
- 右侧是**本页导航**（当前这一讲的小节目录），有三种打开方式：
  1. 鼠标移到**屏幕最右边缘**（48px 内）会自动抽出；
  2. 点右侧那条**蓝色竖条把手**（写着「本页导航」，一直可见）；
  3. 点顶栏的 **☰** 按钮（它同时也是"感应开关"）。
- 抽屉打开后：
  - **钉住** —— 让它固定展开，鼠标移开也不收回；再点一下取消；
  - **✕** 或按键盘 <span class="kbd">Esc</span> —— 立即收起；
  - 点目录里的小节标题 —— 跳到该小节并自动收起（钉住时除外）。
- 顶栏 **☰** 按钮控制"感应"是否启用：关闭后鼠标移到右边缘不再自动抽出，右边那条蓝色把手也会隐藏，
  避免误触；需要时再点一次即可恢复。
- 右上角 `◐` 切换深色 / 浅色主题，`⎙` 打印或导出 PDF（打印时折叠的答案会自动展开）。
- **键盘快捷键**：`←` `→` 单步看动画，`空格` 播放 / 暂停，`Esc` 收起右侧导航，`Alt`+`←/→` 翻到上一讲 / 下一讲。

## 为什么分成 15 个 HTML 而不是一个大文件

左侧目录可以跳到任意一讲，看起来"合起来就是一本书"，但拆成多页是有实际好处的：

| 维度 | 15 个页面（现在这样） | 合成单文件 |
|---|---|---|
| 体积 | 每页 50~370 KB，**按需加载** | 一个 3.6 MB 的文件，打开即全部解析 |
| 动画 | 只初始化当前这一讲的 4~9 个动画（几十~几百帧） | 81 个动画、2565 帧同时建 DOM，**明显卡顿** |
| 打印 | `⎙` 只导出当前这一讲，方便印发 | 会把整本书打进 PDF |
| 定位 | 每讲有独立文件名，可直接发链接、加书签、单独备份 | 只能给整本一个链接 |
| 容错 | 某一讲的脚本出错，**其它 14 讲照常可用** | 一处出错可能整本打不开 |
| 维护 | 改一讲不碰其它文件，便于多人协作 / 后续增补 | 每次修改都要动同一个大文件 |

代价只有一个：**跨章节搜索不方便**（`Ctrl+F` 只搜当前这一讲）。如果需要全文检索，
用编辑器的"在文件夹中查找"即可；如果你确实更想要单文件版本，说一声，我可以再生成一个合并版
（但那会失去上面这些好处，所以默认没有这么做）。

## 关于动画

每个交互动画都有一套统一的操作栏：

| 按钮 | 作用 |
|---|---|
| ▶ 播放 / ⏸ 暂停 | 自动逐帧演示 |
| ◀ 上一步 / 下一步 ▶ | 单步观察，配合说明栏逐帧理解 |
| ⏮ 重来 / ⏭ 末帧 | 跳到开头 / 结尾 |
| 速度滑杆 | 复杂算法建议调慢 |

颜色约定：<b>蓝色</b> = 当前处理位置，<b>橙色</b> = 正在比较，<b>绿色</b> = 已完成/已就位，<b>红色</b> = 冲突或交换。

## 关于「工程视角」小节

课本上的结构容易让人觉得「只是为了考试」。所以**除第 14 讲（题单）与第 15 讲（速查）外，每一讲都设了一节
「工程视角」**，专门回答「这个结构在真实的操作系统 / 数据库 / 网络系统里到底出现在哪、
为什么选它、代价是什么」。篇幅按该章内容在工程中的使用频率分配，从 1.5 千字到 8 千字不等。例如：

| 讲次 | 小节 | 讲了什么 |
|---|---|---|
| 01 | 1.16 | 内存层次与延迟数量级、缓存行与局部性（实测行/列遍历差 **5.4 倍**）、为什么「大 O 相同」实测能差几倍、O(n²) 在小 n 上真的会赢 |
| 02 | 2.10 | CPU 缓存与内存布局为什么让顺序表实测快过链表、动态数组的均摊扩容、内核 free list、LRU 缓存为什么必须「哈希表 + **双向**链表」 |
| 03 | 3.12 | 函数调用栈与栈帧布局、栈溢出（含 8MB 数组放在 1MB 栈上直接崩的真实 bug）、缓冲区溢出攻击与金丝雀/NX/ASLR、栈式虚拟机字节码 |
| 04 | 4.14 | 消息队列的解耦/异步/削峰**及其代价**（积压、重复、顺序性、lag）、生产者-消费者与有界缓冲区、OS 就绪队列与 IO 电梯、bufferbloat、网卡环形缓冲 |
| 05 | 5.7 | grep/编辑器为什么用 BM 而不用 KMP、glibc 的 Two-Way 算法、数据库 `LIKE '%x%'` 为什么退化成逐行匹配、倒排索引、入侵检测与基因比对为何必须用 KMP |
| 06 | 6.9 | 行优先 vs 列优先的实测差距、对称矩阵压缩在有限元与 GPU 显存里的意义、三对角与追赶法、**COO 建 / CSR 算 / CSC 按列 / BSR 上 GPU**、SpMV 与 PageRank、稠密 vs 稀疏的临界点 |
| 07 | 7.11 | B+ 树为什么一个结点就是一页、树高 3 层如何撑住几千万行、叶子链表与范围查询、文件系统目录树与 inode、并查集与赫夫曼编码的工业落点 |
| 08 | 8.10 | 真实图的规模（30 亿用户 vs 8 个顶点）、三种存法的空间账、CSR 与链式前向星的分工、DFS 在编译/GC 里的落点与**递归爆栈**（实测约 7.5 万层触顶）、外存与图数据库 |
| 09 | 9.9 | 地图导航为什么必须用 A\*（含可跑代码实测：带墙网格上 A\* 扩展 81 个结点、Dijkstra 要 1578 个）、OSPF 用 Dijkstra 而 RIP 用 Bellman-Ford、Make/npm 的拓扑排序与循环依赖检测、项目管理关键路径法 |
| 10 | 10.8 | 为什么拉链法比开放定址更主流、扩容为什么翻倍以及 O(n) 长尾延迟（Redis 渐进式 rehash）、抗哈希碰撞攻击、数据库索引为什么用 B+ 树而非哈希、布隆过滤器（实测假阳性 0.96%）与一致性哈希 |
| 11 | 11.11 | 生产级标准库排序的取舍、插入排序在小区间上的真实优势、快排最坏退化与**复杂度攻击**（实测有序输入慢 3500~4600 倍）、稳定性的生产后果、外部排序（100 GB + 4 GB 内存的账）、堆的真实用途是优先队列 |
| 12 | 12.11 | Timsort 的 run 与归并栈、内省排序为什么取 2⌊log₂n⌋ 与 16、pdqsort 与分支预测、多键排序与不稳定的四类生产后果、并行与 MapReduce shuffle、外部排序参数怎么定、「不要排序」往往是最好的优化 |
| 13 | 13.8 | 序列比对（Needleman–Wunsch）、编辑距离与 Viterbi、`git diff` 背后的 LCS、贪心的反例（`{1,3,4}` 找零）、MapReduce 与 FFT、SAT 求解器与正则回溯导致的 ReDoS |

有序输入下朴素快排慢 3500~4600 倍等）。可以当独立读物跳着看。

## 校验工具（可选）

课件内容由三套脚本自动校验，改课件后可以跑一遍确认没有引入错误：

```bash
node tools/batch-check.mjs      # 一键跑完下面六项
node tools/check.mjs            # 结构完整性：文件、锚点、容器、HTML 转义、代码块转义
node tools/nav-check.mjs        # 校验 15 讲的「上一讲 / 下一讲」链条与站内链接
node tools/dom-sim.mjs          # 真实执行页面脚本，并逐帧渲染所有动画，捕获运行时错误
node tools/cpp-check.mjs        # 把课件里每段 C++ 代码抽出来交给 g++ 编译
node tools/coverage-check.mjs   # 按需求清单逐项核对知识点是否都讲到了（含「工程视角」小节硬检查）
node tools/xref-check.mjs       # 正文里「见第 NN 讲」的讲次编号有没有指错
node tools/stats.mjs            # 统计规模数据（字数 / 图解 / 代码块 / 动画）
node tools/verify-stats.mjs     # 核对本页那张规模表与实测是否一致
```

`cpp-check.mjs` 需要系统里有 `g++`；其余几个只需要 Node.js（无需安装任何依赖）。

## 学习建议

1. **先看结构图**，把「数据在内存里长什么样」想清楚，比背代码重要十倍。
2. **再跑动画**：先看整体节奏，再单步抠细节，注意每帧说明栏在讲什么。
3. **后写代码**：代码块右上角可一键复制，但务必自己敲一遍并单步调试。
4. **最后做题**：第 14 讲的洛谷题单按难度分层，做完再回头看讲义会有全新理解。

> 数据结构不是「背下来的画」，而是「想清楚的过程」。
> 每学一个结构，先问三个问题：它在内存里怎么排？基本操作要动几个指针或挪几个元素？这些操作各是什么复杂度？

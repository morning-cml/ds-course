# 数据结构与算法设计 · 交互式课件

一套面向 C++ 学习者的**可交互、可离线**课件。所有抽象概念配结构图，所有核心算法配可单步 / 可自动播放的动态演示，
所有示例代码均为可直接编译运行的 C++。

| 规模 | 数量 |
|---|---|
| 讲次 | 16 讲 + 总览页 |
| 正文 | 约 23.0 万字（另含代码内注释约 4.6 万字） |
| 可单步交互动画 | 80 个（逐帧渲染共 2545 帧） |
| 静态结构图解 | 160 张内联 SVG（其中 6 张为可翻页的静态分步图） |
| C++ 代码 | 236 段，234 段通过 g++ 编译校验（另有 2 段是引用上下文变量的片段） |

> 以上数字由 `node tools/stats.mjs` 实测得出，改课件后请重新跑一遍并同步本表。

## 快速开始

**双击 `index.html`** 即可开始学习。不需要安装任何东西，不需要联网。

- 建议用 Chrome / Edge / Firefox 打开（支持深色主题与打印导出 PDF）。
- 左侧是**课程章节目录**，点任意一讲即可跳过去，当前所在的一讲会高亮。
- 右侧是**本页导航**（当前这一讲的小节目录），有三种打开方式：
  1. 鼠标移到**屏幕最右边缘**（48px 内）会自动抽出；
  2. 点右侧那条**蓝色竖条把手**（写着「本页导航」，一直可见）；
  3. 点顶栏的 **☰** 按钮（它同时也是"感应开关"）。
- 抽屉打开后：
  - **钉住** —— 让它固定展开，鼠标移开也不收回；再点一下取消；
  - **✕** 或按键盘 <span class="kbd">Esc</span> —— 立即收起；
  - 点目录里的小节标题 —— 跳到该小节并自动收起（钉住时除外）。
- 顶栏 **☰** 按钮控制"感应"是否启用：关闭后鼠标移到右边缘不再自动抽出，右边那条蓝色把手也会隐藏，
  避免误触；需要时再点一次即可恢复。
- 右上角 `◐` 切换深色 / 浅色主题，`⎙` 打印或导出 PDF（打印时折叠的答案会自动展开）。
- **键盘快捷键**：`←` `→` 单步看动画，`空格` 播放 / 暂停，`Esc` 收起右侧导航，`Alt`+`←/→` 翻到上一讲 / 下一讲。

## 为什么分成 16 个 HTML 而不是一个大文件

左侧目录可以跳到任意一讲，看起来"合起来就是一本书"，但拆成多页是有实际好处的：

| 维度 | 16 个页面（现在这样） | 合成单文件 |
|---|---|---|
| 体积 | 每页 50~360 KB，**按需加载** | 一个约 3 MB 的文件，打开即全部解析 |
| 动画 | 只初始化当前这一讲的 4~9 个动画（几十~几百帧） | 80 个动画、2545 帧同时建 DOM，**明显卡顿** |
| 打印 | `⎙` 只导出当前这一讲，方便印发 | 会把整本书打进 PDF |
| 定位 | 每讲有独立文件名，可直接发链接、加书签、单独备份 | 只能给整本一个链接 |
| 容错 | 某一讲的脚本出错，**其它 15 讲照常可用** | 一处出错可能整本打不开 |
| 维护 | 改一讲不碰其它文件，便于多人协作 / 后续增补 | 每次修改都要动同一个大文件 |

代价只有一个：**跨章节搜索不方便**（`Ctrl+F` 只搜当前这一讲）。如果需要全文检索，
用编辑器的"在文件夹中查找"即可；如果你确实更想要单文件版本，说一声，我可以再生成一个合并版
（但那会失去上面这些好处，所以默认没有这么做）。

## 关于动画

每个交互动画都有一套统一的操作栏：

| 按钮 | 作用 |
|---|---|
| ▶ 播放 / ⏸ 暂停 | 自动逐帧演示 |
| ◀ 上一步 / 下一步 ▶ | 单步观察，配合说明栏逐帧理解 |
| ⏮ 重来 / ⏭ 末帧 | 跳到开头 / 结尾 |
| 速度滑杆 | 复杂算法建议调慢 |

颜色约定：<b>蓝色</b> = 当前处理位置，<b>橙色</b> = 正在比较，<b>绿色</b> = 已完成/已就位，<b>红色</b> = 冲突或交换。

## 校验工具（可选）

课件内容由多套脚本自动校验，改课件后可以跑一遍确认没有引入错误：

```bash
node tools/batch-check.mjs      # 一键跑完下面十一项
node tools/check.mjs            # 结构完整性：文件、锚点、容器、HTML 转义、代码块转义
node tools/nav-check.mjs        # 校验 16 讲的「上一讲 / 下一讲」链条与站内链接
node tools/dom-sim.mjs          # 真实执行页面脚本，并逐帧渲染所有动画，捕获运行时错误
node tools/frame-check.mjs      # 动画帧状态：画面会不会「冻结在最终态」（draw 读了活变量）
node tools/vz-check.mjs         # 动画用到的 vz-* 状态类是否都在 course.css 里有定义
node tools/cpp-check.mjs        # 把课件里每段 C++ 代码抽出来交给 g++ 编译
node tools/coverage-check.mjs   # 按需求清单逐项核对知识点是否都讲到了
node tools/xref-check.mjs       # 正文里「见第 NN 讲」的讲次编号有没有指错
node tools/verify-stats.mjs     # 公开文档里的规模数字与实测是否一致
node tools/print-check.mjs      # 代码配色：浅色/深色/打印三套配色是否都看得清（对比度 ≥ 4.5:1）
node tools/deploy-check.mjs     # 上线自检：路径大小写、绝对路径、入口文件（Windows 查不出来的那些）
node tools/stats.mjs            # 统计规模数据（字数 / 图解 / 代码块 / 动画）
```

> `frame-check.mjs` 还可以当调试工具用：
> `node tools/frame-check.mjs --report` 打印每个动画的详细指标，
> `node tools/frame-check.mjs --dump viz-prim ch09-viz.js` 把某个动画若干帧**真正画出来的文字**打出来，
> 用来核对「第 0 帧的画面和它 desc 说的是不是一回事」；
> `node tools/frame-check.mjs --fingerprint` 输出**所有动画全部帧的渲染指纹** ——
> 只改注释或做重构时，改动前后各跑一次，指纹一致就证明渲染行为没变。

`cpp-check.mjs` 需要系统里有 `g++`；其余几个只需要 Node.js（无需安装任何依赖）。

## 部署到网上（让学生随时打开）

这套课件是**纯静态**的：没有构建步骤、没有服务端、没有外部 CDN，所有样式脚本都在
`assets/` 里。所以它可以原样丢到任何静态托管上，学生用浏览器打开链接就能看。

以 **Cloudflare Pages**（免费版就够：20000 个文件 / 单文件 25 MiB / 每月 500 次构建，
本站约 55 个文件、3.9 MiB）为例：

1. Cloudflare 控制台 → Workers & Pages → Create → Pages → **Connect to Git**，选中本仓库。
2. 构建设置：
   - **Framework preset**：`None`
   - **Build command**：**留空**（不需要构建）
   - **Build output directory**：`ds-course` ← 注意是仓库里的子目录，不是根目录
3. 保存并部署，几十秒后会得到 `https://<项目名>.pages.dev`；之后每次 `git push` 都会自动重新发布。
4. 想用自己的域名，在项目的 Custom domains 里加一条 CNAME 即可。

几点提醒：

- **上线前先跑 `node tools/deploy-check.mjs`**。本机是 Windows（不区分大小写），
  而托管商都是 Linux（区分大小写），`assets/CSS/x.css` 这种笔误在本地完全正常、上线就 404。
- 部署后反而**比本地双击打开更好用**：`file://` 下浏览器会禁用剪贴板 API
  （代码块的「复制」按钮会退化成旧方案）、部分浏览器还会禁用 localStorage（主题选择记不住）；
  HTTPS 下这两个限制都没有。
- 部分国内网络访问 `*.pages.dev` 可能不稳定或较慢。若学生主要在国内，
  可以考虑腾讯云 EdgeOne Pages、Gitee Pages，或把 `ds-course/` 整个目录打包发给学生
  （课件本来就设计成离线可用，双击 `index.html` 即可）。
- 发布目录选 `ds-course` 后，仓库根目录的 `README.md`、`GIT-使用说明.md`、`git-commit.ps1` 不会发布；
  但 **`ds-course/` 里的** `README.md`、`SPEC*.md`、`REPORT-*.md`、`package.json`、`tools/` 会一起发布，
  知道路径就能直接访问。它们不影响课件使用，也不含私人信息。
  如果只想发布课件本身，把构建设置改成：
  - **Build command**：`mkdir -p dist && cp -r ds-course/index.html ds-course/ch*.html ds-course/assets dist/`
  - **Build output directory**：`dist`

## 学习建议

1. **先看结构图**，把「数据在内存里长什么样」想清楚，比背代码重要十倍。
2. **再跑动画**：先看整体节奏，再单步抠细节，注意每帧说明栏在讲什么。
3. **后写代码**：代码块右上角可一键复制，但务必自己敲一遍并单步调试。
4. **最后做题**：第 14 讲的洛谷题单按难度分层，做完再回头看讲义会有全新理解。

> 数据结构不是「背下来的画」，而是「想清楚的过程」。
> 每学一个结构，先问三个问题：它在内存里怎么排？基本操作要动几个指针或挪几个元素？这些操作各是什么复杂度？
